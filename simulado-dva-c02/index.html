Questão 1 · Desenvolvimento com os serviços da AWS

Um time de desenvolvimento está criando uma aplicação web que utilizará Amazon S3 para armazenar arquivos enviados pelos usuários. O time deseja reduzir o acoplamento entre a aplicação e o bucket S3, permitindo que a aplicação faça upload diretamente para o S3 sem que o backend precise receber os arquivos. Qual abordagem é a MAIS apropriada para atender a esse requisito?

  1. Configurar um Application Load Balancer (ALB) na frente do bucket S3 para receber os uploads e repassá-los ao bucket
  2. Gerar URLs pré-assinadas (pre-signed URLs) no backend para que o cliente faça upload diretamente para o bucket S3
  3. Criar um endpoint do API Gateway que receba o arquivo e o encaminhe para o bucket S3 usando integração proxy
  4. Conceder acesso público de escrita ao bucket S3 e permitir que o cliente envie arquivos diretamente usando o endpoint público
Ver resposta comentada

Resposta: B) Gerar URLs pré-assinadas (pre-signed URLs) no backend para que o cliente faça upload diretamente para o bucket S3

Resposta correta: Gerar URLs pré-assinadas (pre-signed URLs) no backend para que o cliente faça upload diretamente para o bucket S3

Por quê: Esta alternativa é a mais adequada porque o backend apenas gera URLs pré-assinadas (pre-signed URLs) com permissões e tempo de expiração controlados. O cliente faz o upload diretamente para o S3 usando essa URL, reduzindo o acoplamento e evitando que o backend faça o tráfego de dados, ao mesmo tempo em que mantém segurança e controle de acesso via IAM e políticas do bucket.

Dica de prova: Quando o enunciado falar em 'upload direto para o S3', 'reduzir acoplamento' e 'não trafegar o arquivo pelo backend', pense em URLs pré-assinadas (pre-signed URLs) como a solução padrão e recomendada pela AWS.

Questão 8 · Troubleshooting e Otimização

Em horários de pico, as mensagens começam a acumular na fila e o tempo de processamento total aumenta bastante. O CloudWatch Logs mostra que a função Lambda frequentemente atinge o limite de tempo (timeout) ao chamar uma API externa de pagamento, e as métricas indicam aumento de erros e retries. O desenvolvedor precisa otimizar a solução para reduzir o acúmulo de mensagens e os timeouts, mantendo custos sob controle. Qual é a MELHOR abordagem?

  1. Usar Timeout e backoff nas chamadas à API, timeout menor na função, visibility timeout da fila acima dele e concorrência controlada
  2. Configurar a função Lambda para usar uma VPC com NAT Gateway e habilitar o provisioned concurrency, sem alterar a lógica de integração com a API externa.
  3. Aumentar o timeout da função Lambda para o valor máximo permitido e elevar a memória para o dobro, mantendo a mesma lógica de chamadas síncronas à API externa.
  4. Habilitar DLQ na função Lambda e reduzir o 'visibility timeout' da fila SQS para que as mensagens sejam rapidamente reenviadas à função até que o processamento seja concluído.
Ver resposta comentada

Resposta: A) Usar Timeout e backoff nas chamadas à API, timeout menor na função, visibility timeout da fila acima dele e concorrência controlada

Resposta correta: Usar Timeout e backoff nas chamadas à API, timeout menor na função, visibility timeout da fila acima dele e concorrência controlada

Por quê: Esta alternativa é a melhor solução por abordar o problema de forma completa e orientada a boas práticas. Ao implementar timeout e retries com backoff exponencial na chamada à API externa, a função passa a lidar melhor com instabilidades do serviço de terceiros, evitando waits longos desnecessários. Reduzir o timeout da função Lambda faz com que falhas ocorram mais rapidamente (fail fast), liberando recursos e evitando que a função fique presa em chamadas muito longas.

Dica de prova: SQS + Lambda exige alinhamento entre 'visibility timeout' da fila e timeout da função. 'visibility timeout' deve ser sempre MAIOR que o timeout da Lambda para evitar processamento duplicado.

Questão 9 · Desenvolvimento com os serviços da AWS

  2. Aumentar a memória da função AWS Lambda, pois isso eleva o limite de concorrência automaticamente e elimina erros de 429 no API Gateway.
  3. Criar uma fila Amazon SQS entre o API Gateway e a função Lambda para enfileirar as requisições síncronas HTTP.
  4. Ativar caching de respostas no API Gateway com TTL muito alto para as rotas, evitando que as requisições cheguem à função Lambda.
Ver resposta comentada

Resposta: A) Usar Throttling por estágio no API Gateway com limites de burst e rate, e retry exponencial no cliente ao receber 429

Resposta correta: Usar Throttling por estágio no API Gateway com limites de burst e rate, e retry exponencial no cliente ao receber 429

Ao configurar o throttling em nível de estágio ou de método, você controla explicitamente quantas requisições por segundo são permitidas e como o sistema reage a picos.

Questão 11 · Segurança

Uma equipe precisa garantir que apenas funções AWS Lambda específicas possam descriptografar segredos armazenados em um bucket Amazon S3 usando AWS KMS. Qual abordagem é mais adequada para atender a esse requisito de segurança com o menor esforço operacional?

  2. Criar uma CMK no AWS KMS, usar essa chave para criptografar os segredos e definir uma key policy que permita o uso da chave apenas para as funções Lambda específicas
  3. Utilizar criptografia no lado do cliente, armazenar os segredos já criptografados em S3 e permitir que qualquer recurso da conta acesse os objetos
  4. Armazenar os segredos em texto puro no S3 e usar uma policy de bucket para limitar o acesso apenas às funções Lambda específicas
Ver resposta comentada

Resposta: B) Criar uma CMK no AWS KMS, usar essa chave para criptografar os segredos e definir uma key policy que permita o uso da chave apenas para as funções Lambda específicas

Resposta correta: Criar uma CMK no AWS KMS, usar essa chave para criptografar os segredos e definir uma key policy que permita o uso da chave apenas para as funções Lambda específicas

Por quê: Esta alternativa é a mais adequada porque utiliza uma chave gerenciada pelo cliente (CMK) no AWS KMS com uma key policy bem definida. Essa key policy pode restringir explicitamente o uso da chave apenas às funções Lambda desejadas, garantindo que somente essas funções possam chamar as operações de decrypt no KMS. Use CMKs para granularidade de acesso mais fina do que SSE-S3 padrão.

Questão 12 · Troubleshooting e Otimização

Um sistema de processamento de pedidos em produção, executando em instâncias Amazon EC2 por trás de um Application Load Balancer (ALB), está apresentando aumento de latência e alguns erros 5xx intermitentes durante picos de tráfego.
