Questão 1 de 12 · Implementar recursos de IA em soluções de banco de dados

A equipe da Agência de Notícias Fato Real migrou a busca de matérias de kNN exato para uma busca aproximada com índice vetorial. O editor-chefe quer um indicador que mostre quanto a busca aproximada se afasta da exata ao retornar os vizinhos mais próximos. Qual métrica a equipe deve acompanhar?

Resposta: D) Recall, isto é, a proporção dos vizinhos exatos que a busca aproximada também retorna

Por quê: Na busca vetorial aproximada (ANN), troca-se um pouco de exatidão por grande ganho de velocidade. O recall mede a fração dos vizinhos exatos encontrada pelo algoritmo e é a medida de qualidade da aproximação; valores próximos de 1 indicam resultados quase iguais aos do kNN.

Dica de prova: Qualidade da busca aproximada frente à exata: recall.

Referência: Busca vetorial e índices vetoriais

Questão 2 de 12 · Projetar e desenvolver soluções de banco de dados

O procedimento dbo.TransferirSaldo da Cooperativa de Crédito União Rural debita uma conta e credita outra dentro de BEGIN TRANSACTION. Em um teste, o crédito falhou por violação de restrição e o débito ficou gravado. A equipe quer reverter tudo em caso de erro e devolver a mensagem original ao aplicativo. Qual estrutura atende?

Resposta: C) BEGIN TRY com a transação e o COMMIT; no BEGIN CATCH, IF @@TRANCOUNT > 0 ROLLBACK e depois THROW;

Por quê: O padrão recomendado é: transação dentro do TRY, COMMIT no fim do TRY e, no CATCH, ROLLBACK condicionado a @@TRANCOUNT > 0 (ou XACT_STATE() diferente de 0) seguido de THROW para relançar o erro com número, mensagem e estado originais.

Dica de prova: TRY com COMMIT; CATCH com IF @@TRANCOUNT > 0 ROLLBACK + THROW.

Referência: TRY...CATCH (Transact-SQL)

Referência: Branches, pull requests e resolução de conflitos

Questão 4 de 12 · Implementar recursos de IA em soluções de banco de dados

No portal de receitas Sabor de Casa, usuários buscam por frases como assando bolos de cenoura e esperam encontrar receitas com assar, asse ou bolo, sem precisar escrever as variações. A coluna ModoPreparo tem índice de texto completo. Qual predicado atende de forma mais direta?

Resposta: D) FREETEXT(ModoPreparo, 'assando bolos de cenoura')

Por quê: CONTAINS dá controle preciso (termos, frases, prefixos, FORMSOF, NEAR). FREETEXT busca correspondências de significado e gera formas flexionadas automaticamente. CONTAINSTABLE e FREETEXTTABLE fazem o mesmo retornando KEY e RANK.

Dica de prova: Busca em linguagem natural com variações automáticas: FREETEXT.

Referência: Consultar com pesquisa de texto completo

Questão 5 de 12 · Projetar e desenvolver soluções de banco de dados

A Cooperativa de Laticínios Leite Puro tem, no Microsoft Fabric, um lakehouse com dados de coleta e um warehouse financeiro, em workspaces diferentes. Os analistas querem conversar com o GitHub Copilot no VS Code e pedir que ele gere e execute T-SQL sobre o SQL analytics endpoint do lakehouse, respeitando as permissões do Fabric. Para a equipe de coleta, a conexão deve ficar presa ao lakehouse, sem que o usuário precise informar em toda conversa qual item usar; já o time de finanças quer escolher o warehouse pelo prompt. Qual configuração do servidor MCP remoto do Fabric Data Warehouse atende aos dois times?

Resposta: A) Coleta com o endpoint por item, com workspace e item no caminho; finanças com o endpoint global, informando o warehouse no prompt

Por quê: Para conectar agentes a lakehouses e warehouses do Fabric, o servidor MCP remoto do Fabric Data Warehouse oferece endpoint global (contexto pelo prompt) e endpoint por item (workspace e item na URL), com a ferramenta executeSQL e respeito às permissões do Fabric. Outra opção é publicar um data agent do Fabric como servidor MCP.

Dica de prova: MCP do Fabric DW: endpoint por item fixa o item; global recebe o item pelo prompt.

Referência: Servidor MCP do Fabric Data Warehouse

Questão 6 de 12 · Proteger, otimizar e implantar soluções de banco de dados

A Operadora de Planos de Saúde Vital usa Always Encrypted na coluna NumeroCarteirinha. A aplicação precisa localizar beneficiários por igualdade nessa coluna e fazer junções com outra tabela pelo mesmo valor, sem usar enclaves seguros. Qual tipo de criptografia a coluna deve usar?

Resposta: A) Determinística, que gera sempre o mesmo valor cifrado para o mesmo texto

Por quê: No Always Encrypted, a criptografia determinística permite igualdade, junções, GROUP BY e índices; a aleatória é mais segura e, sem enclave, não permite operações na coluna cifrada.

Dica de prova: Precisa de igualdade ou junção na coluna cifrada sem enclave: determinística.

Referência: Always Encrypted: tipos de criptografia

Questão 8 de 12 · Projetar e desenvolver soluções de banco de dados

A Rede de Metrô Cidade Rápida modelou estações como nó Estacao e trechos como borda Liga. O planejamento quer, para a estação Centro, todas as estações alcançáveis em até 4 trechos e o número de trechos do caminho mais curto até cada uma. Qual construção usar?

Resposta: D) MATCH(SHORTEST_PATH(e1(-(l)->e2){1,4})) com FOR PATH em Liga e Estacao e COUNT(...) WITHIN GROUP (GRAPH PATH)

Por quê: SHORTEST_PATH encontra o menor caminho em padrões de comprimento arbitrário, com quantificadores + (um ou mais) ou {1,n}. As tabelas do padrão recebem FOR PATH e os dados do caminho são obtidos com funções WITHIN GROUP (GRAPH PATH).

Dica de prova: Alcançáveis em até N saltos com menor caminho: SHORTEST_PATH com {1,N} e FOR PATH.

Referência: SHORTEST_PATH no SQL Graph

Questão 9 de 12 · Proteger, otimizar e implantar soluções de banco de dados

No sistema de reservas da Pousada Mar Azul, dois atendentes podem abrir a mesma reserva, editar na tela por alguns minutos e salvar. Hoje a última gravação sobrescreve a anterior sem aviso. A equipe não quer manter bloqueios enquanto a tela está aberta. Qual solução detecta a alteração concorrente no momento de salvar?

Resposta: D) Usar uma coluna rowversion e incluir no WHERE do UPDATE o valor lido, conferindo @@ROWCOUNT

Por quê: rowversion é um número binário gerado automaticamente e único no banco, alterado a cada INSERT ou UPDATE da linha. Comparar o valor lido com o atual no UPDATE implementa concorrência otimista e evita atualização perdida sem manter bloqueios.

Dica de prova: Detectar que alguém salvou antes de mim sem bloquear: rowversion no WHERE do UPDATE.

Referência: rowversion (Transact-SQL)

A Biblioteca Jurídica Norma Clara vai dividir cada documento em vários chunks e gerar um embedding por chunk. A equipe quer controlar o espaço ocupado pelos vetores e poder regenerá-los sem tocar na tabela de documentos. Qual modelagem é a mais indicada?

Por quê: Um padrão de projeto é armazenar os vetores em uma tabela dedicada, com uma linha por chunk e chave para a linha de origem. Isso facilita acompanhar o espaço consumido e reconstruir embeddings sem alterar os dados de negócio.

Questão 11 de 12 · Projetar e desenvolver soluções de banco de dados

Um procedimento de pesquisa da Imobiliária Bom Teto monta SQL dinâmico concatenando o valor digitado pelo usuário em WHERE Bairro = ' + @Bairro + '. Um teste de segurança conseguiu executar comandos extras. Qual reescrita corrige a vulnerabilidade mantendo o SQL dinâmico?

Resposta: D) Usar sp_executesql com WHERE Bairro = @b e @Bairro como parâmetro

Por quê: Para SQL dinâmico seguro, use sp_executesql com @params declarados e valores passados como parâmetros; para nomes de objetos dinâmicos, valide contra uma lista e use QUOTENAME. Isso evita injeção de SQL e favorece a reutilização de planos.

Dica de prova: SQL dinâmico com entrada do usuário: sp_executesql parametrizado.

Referência: sp_executesql (Transact-SQL)

A Editora Página Viva expõe o catálogo de livros pelo Data API builder. A equipe habilitou "runtime": {"cache": {"enabled": true, "ttl-seconds": 60}}, mas as requisições REST à entidade Livro continuam indo ao banco toda vez. O que falta configurar?

Resposta: D) Habilitar o cache também na entidade Livro, com cache.enabled: true

Por quê: No Data API builder, o cache é ligado em runtime.cache e cada entidade precisa habilitar cache.enabled; ttl-seconds pode ser definido nos dois níveis, com o valor da entidade prevalecendo. O cache é invalidado quando os dados são alterados pela API.

Dica de prova: Cache do DAB: ligar no runtime E na entidade.

Referência: Cache nível 1 no Data API builder
