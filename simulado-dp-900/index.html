Questão 1 de 12 · Descrever conceitos fundamentais de dados

Por que a normalização ajuda as gravações em um sistema transacional?

Resposta: A) Cada dado fica em um só lugar, com uma única atualização

Por quê: Em OLTP, a normalização reduz a duplicação e o risco de anomalias, tornando as gravações mais simples e seguras.

Dica de prova: Normalizado: um dado, um lugar, uma atualização.

Referência: Microsoft Learn: normalização

Questão 2 de 12 · Descrever considerações para dados não relacionais no Azure

Como o Azure Cosmos DB trata a indexação dos documentos por padrão?

Resposta: B) Indexa todas as propriedades de forma automática

Por quê: O Cosmos DB indexa automaticamente todos os dados, sem esquema nem índices definidos pelo usuário. A política de indexação pode ser ajustada para reduzir custo.

Dica de prova: Cosmos DB indexa tudo por padrão.

Referência: Indexação no Azure Cosmos DB

Questão 3 de 12 · Descrever uma carga de trabalho de análise

No Microsoft Fabric, qual componente é o data lake único e lógico de toda a organização?

Resposta: D) OneLake

Por quê: O OneLake é o armazenamento central do Microsoft Fabric, criado automaticamente para cada locatário, com dados em formato Delta Parquet.

Dica de prova: Data lake único do Fabric: OneLake.

Referência: O que é o OneLake

Questão 4 de 12 · Identificar considerações para dados relacionais no Azure

A tabela de pedidos repete o nome e o endereço do cliente em cada linha. O que a normalização faria nesse caso?

Resposta: D) Levaria os dados do cliente para outra tabela

Por quê: Normalizar é separar entidades em tabelas próprias. Assim, alterar o endereço do cliente exige mudar uma única linha.

Dica de prova: Dado repetido em cada linha: separar em outra tabela.

Referência: Microsoft Learn: normalização

Questão 5 de 12 · Descrever conceitos fundamentais de dados

Em um banco de documentos, é comum guardar os itens do pedido dentro do próprio documento do pedido. Qual é a vantagem dessa modelagem?

Resposta: C) Ler o pedido inteiro em uma operação, sem joins

Por quê: Em bancos de documentos, dados lidos juntos costumam ser incorporados no mesmo documento, reduzindo idas ao banco e dispensando joins.

Dica de prova: Documento com tudo dentro: uma leitura, sem join.

Referência: Modelagem de dados no Azure Cosmos DB

Questão 6 de 12 · Descrever considerações para dados não relacionais no Azure

Uma aplicação grava linhas de log continuamente no fim de um mesmo arquivo no Armazenamento de Blobs. Qual tipo de blob é o mais indicado?

Resposta: A) Blob de acréscimo

Por quê: O Blob Storage tem três tipos: blobs de blocos (arquivos em geral), de acréscimo (logs) e de páginas (acesso aleatório, como discos de VM).

Dica de prova: Log que só cresce no fim: blob de acréscimo.

Referência: Blobs de blocos, de acréscimo e de páginas

Questão 7 de 12 · Descrever uma carga de trabalho de análise

Para que serve o endpoint de análise SQL de um lakehouse no Microsoft Fabric?

Resposta: A) Consultar as tabelas Delta com T-SQL, em modo de leitura

Por quê: Cada lakehouse do Fabric tem um endpoint de análise SQL criado automaticamente, que expõe as tabelas Delta para consultas T-SQL somente leitura.

Dica de prova: Lakehouse + T-SQL de leitura: endpoint de análise SQL.

Referência: Endpoint de análise SQL do lakehouse

Questão 8 de 12 · Identificar considerações para dados relacionais no Azure

Qual condição SQL retorna os clientes cujo nome começa com Ana?

Resposta: D) WHERE Nome LIKE 'Ana%'

Por quê: O operador LIKE usa curingas: % para qualquer sequência e _ para um caractere.

Dica de prova: Começa com: LIKE 'texto%'.

Referência: LIKE (Transact-SQL)

Questão 9 de 12 · Descrever conceitos fundamentais de dados

A diretoria quer comparar o faturamento por região nos últimos cinco anos, somando milhões de vendas. Que tipo de carga de trabalho é essa?

Resposta: D) Analítica (OLAP)

Por quê: Cargas analíticas leem e agregam grandes volumes de dados históricos para apoiar decisões, normalmente em data warehouses, lakehouses ou modelos semânticos.

Dica de prova: Somar e comparar histórico: analítica.

Referência: Microsoft Learn: cargas analíticas

Questão 10 de 12 · Descrever considerações para dados não relacionais no Azure

Ao criar uma conta do Azure Cosmos DB, como a API, como NoSQL ou MongoDB, é definida?

Resposta: A) É escolhida por conta, na criação

Por quê: A API é definida na conta. Para usar outra API, cria-se outra conta e, se preciso, migram-se os dados.

Dica de prova: API do Cosmos DB: escolhida na conta.

Referência: Escolher uma API no Azure Cosmos DB

Questão 11 de 12 · Descrever uma carga de trabalho de análise

Qual visual lista valores detalhados em linhas e colunas simples, como cada pedido com cliente, data e valor?

Resposta: A) Tabela

Por quê: Tabelas mostram valores exatos linha a linha. Matrizes cruzam categorias em linhas e colunas, com subtotais.

Dica de prova: Lista detalhada de registros: tabela.

Referência: Visuais de tabela no Power BI

Questão 12 de 12 · Identificar considerações para dados relacionais no Azure

Um usuário excluiu linhas importantes de um Banco de Dados SQL do Azure há duas horas. Qual recurso permite recuperar o banco como estava antes da exclusão?

Resposta: C) Restauração pontual

Por quê: O Azure SQL faz backups automáticos e permite a restauração pontual (PITR) para um momento dentro do período de retenção.

Dica de prova: Voltar o banco para um momento: restauração pontual.

Referência: Recuperar usando backups automáticos
