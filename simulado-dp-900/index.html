Questão 1 · Descrever conceitos fundamentais de dados

Por que a normalização ajuda as gravações em um sistema transacional?

  1. Cada dado fica em um só lugar, com uma única atualização
  2. Os dados passam a ser gravados em arquivos Parquet
  3. As consultas analíticas deixam de precisar de joins
  4. Todas as informações ficam na mesma tabela larga
Ver resposta comentada

Resposta: A) Cada dado fica em um só lugar, com uma única atualização

Resposta correta: Cada dado fica em um só lugar, com uma única atualização

Por quê: Em OLTP, a normalização reduz a duplicação e o risco de anomalias, tornando as gravações mais simples e seguras.

Dica de prova: Normalizado: um dado, um lugar, uma atualização.

Referência: Microsoft Learn: normalização

Como o Azure Cosmos DB trata a indexação dos documentos por padrão?

  2. Indexa todas as propriedades de forma automática

Questão 4 · Identificar considerações para dados relacionais no Azure

A tabela de pedidos repete o nome e o endereço do cliente em cada linha. O que a normalização faria nesse caso?

  1. Repetiria o endereço também na tabela de produtos
  2. Juntaria pedidos e produtos em uma tabela única
  3. Removeria a chave primária da tabela de pedidos
  4. Levaria os dados do cliente para outra tabela
Ver resposta comentada

Resposta: D) Levaria os dados do cliente para outra tabela

Resposta correta: Levaria os dados do cliente para outra tabela

Por quê: Normalizar é separar entidades em tabelas próprias. Assim, alterar o endereço do cliente exige mudar uma única linha.

Dica de prova: Dado repetido em cada linha: separar em outra tabela.

Referência: Microsoft Learn: normalização

Questão 5 · Descrever conceitos fundamentais de dados

Em um banco de documentos, é comum guardar os itens do pedido dentro do próprio documento do pedido. Qual é a vantagem dessa modelagem?

  1. Permitir chaves estrangeiras entre documentos
  2. Evitar a duplicação de dados entre os pedidos
  3. Ler o pedido inteiro em uma operação, sem joins
  4. Garantir o mesmo esquema para os pedidos
Ver resposta comentada

Resposta: C) Ler o pedido inteiro em uma operação, sem joins

Resposta correta: Ler o pedido inteiro em uma operação, sem joins

Por quê: Em bancos de documentos, dados lidos juntos costumam ser incorporados no mesmo documento, reduzindo idas ao banco e dispensando joins.

Dica de prova: Documento com tudo dentro: uma leitura, sem join.

Referência: Modelagem de dados no Azure Cosmos DB

Questão 6 · Descrever considerações para dados não relacionais no Azure

Uma aplicação grava linhas de log continuamente no fim de um mesmo arquivo no Armazenamento de Blobs. Qual tipo de blob é o mais indicado?

  1. Blob de acréscimo
  2. Blob de páginas
  3. Blob de blocos
  4. Blob de disco gerenciado
Ver resposta comentada

Resposta: A) Blob de acréscimo

Resposta correta: Blob de acréscimo

Por quê: O Blob Storage tem três tipos: blobs de blocos (arquivos em geral), de acréscimo (logs) e de páginas (acesso aleatório, como discos de VM).

Dica de prova: Log que só cresce no fim: blob de acréscimo.

Referência: Blobs de blocos, de acréscimo e de páginas

Questão 8 · Identificar considerações para dados relacionais no Azure

Qual condição SQL retorna os clientes cujo nome começa com Ana?

  1. WHERE Nome = '%Ana'
  2. ORDER BY Nome 'Ana'
  3. GROUP BY Nome 'Ana%'
  4. WHERE Nome LIKE 'Ana%'
Ver resposta comentada

Resposta: D) WHERE Nome LIKE 'Ana%'

Resposta correta: WHERE Nome LIKE 'Ana%'

Por quê: O operador LIKE usa curingas: % para qualquer sequência e _ para um caractere.

Dica de prova: Começa com: LIKE 'texto%'.

Referência: LIKE (Transact-SQL)
