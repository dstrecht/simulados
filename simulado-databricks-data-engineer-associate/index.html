Questão 1 de 12Databricks Intelligence Platform

Na Universidade Corporativa Saber+, analistas usam um cluster all-purpose clássico durante o expediente, mas ele fica ligado à noite e nos fins de semana sem nenhum comando em execução. Qual configuração reduz esse custo sem mudar a forma de trabalho?

✓ Resposta: C) Auto termination com um período de inatividade em minutos

Por quê: Computação encerrada guarda a configuração para ser reiniciada depois. A computação all-purpose é excluída de vez 30 dias após o término, a menos que esteja fixada (pin).

Dica de prova: All-purpose ociosa gastando à toa = auto termination.

Referência: Gerenciar computação clássica: término automático

Questão 2 de 12Governança e segurança

Na Distribuidora de Energia Luz Forte, um sistema de faturamento fora do Databricks grava e lê diretamente arquivos Delta em um bucket, e o Databricks também precisa consultá-los e governá-los no Unity Catalog. Qual tipo de tabela é adequado e por quê?

✓ Resposta: D) Externa, porque o Unity Catalog governa o acesso e o ciclo de vida dos arquivos fica com o outro sistema

Por quê: Tabelas externas são indicadas quando clientes fora do Databricks precisam de acesso direto aos arquivos. Nesse caso, privilégios do Unity Catalog não valem para o acesso direto pelo caminho.

Dica de prova: Arquivos mantidos por outro sistema = tabela externa (governança sem ciclo de vida).

Referência: Gerenciado x externo

Questão 3 de 12Implementação de CI/CD

Na Editora Horizonte, uma engenheira abriu o Git folder do projeto de ETL e precisa começar uma correção sem mexer no branch main, criando um branch novo a partir dele pela interface do workspace. Qual é o caminho?

✓ Resposta: C) Abrir o diálogo Git, clicar em Create Branch, informar o nome e escolher main como base

Por quê: Os Git folders são um cliente Git visual dentro do workspace: pelo diálogo Git é possível criar e trocar de branch, fazer pull, commit e push, merge, rebase e reset.

Dica de prova: Novo branch no workspace = diálogo Git > Create Branch > nome + branch base.

Referência: Criar e gerenciar Git folders

Questão 4 de 12Ingestão e carga de dados

A Construtora Ponte Firme quer ingerir planilhas e PDFs de sites do Microsoft SharePoint para o lakehouse, com autenticação, leitura incremental e novas tentativas tratadas por um serviço configurável, sem escrever código de leitura. Qual opção do Lakeflow Connect atende?

✓ Resposta: B) O conector de arquivos gerenciado do SharePoint, que grava em streaming tables

Por quê: O Lakeflow Connect oferece conectores de arquivos gerenciados, configurados sem código, e padrão, que usam APIs de leitura do Spark e SQL para quem precisa de controle fino sobre a leitura.

Dica de prova: SharePoint sem código de leitura = conector de arquivos gerenciado.

Referência: Conectores de arquivos do Lakeflow Connect

Questão 5 de 12Solução de problemas, monitoramento e otimização

Na Spark UI de um job da Seguradora Âncora, o estágio mais longo tem uma única tarefa, enquanto os demais núcleos do cluster ficam ociosos. O código calcula um ranking com row_number() OVER (ORDER BY valor_total DESC) sobre a tabela inteira. Qual é a causa provável e a correção?

✓ Resposta: D) Janela sem PARTITION BY leva o dataset inteiro a uma tarefa; adicionar PARTITION BY se a lógica permitir

Por quê: Estágios longos com uma tarefa costumam vir de janela sem PARTITION BY, UDF cara sobre poucos dados, arquivos não divisíveis como gzip, multiLine em JSON ou CSV, inferência de esquema em arquivo grande ou repartition(1) e coalesce(1).

Dica de prova: Estágio com uma única tarefa = procure janela sem PARTITION BY, gzip ou coalesce(1).

Referência: Estágio longo com uma única tarefa

Questão 6 de 12Trabalho com Lakeflow Jobs

No job da Indústria Têxtil Fio Forte, a tarefa 1 extrai dados; as tarefas 2 e 3 dependem só da 1; a tarefa 4 depende da 2 e da 3. Como o Lakeflow Jobs executa esse DAG com o Run if padrão?

✓ Resposta: B) Roda 1, depois 2 e 3 em paralelo, e a 4 quando 2 e 3 terminarem com sucesso

Por quê: As dependências formam um grafo acíclico dirigido (DAG). O campo Depends on e as condições Run if definem a ordem e as regras de execução de cada tarefa.

Dica de prova: DAG de job: dependências em sequência, independentes em paralelo.

Referência: Exemplo de job com dependências

Questão 7 de 12Transformação e modelagem de dados

Na Vinícola Serra Gaúcha, registros de sensores chegam com as colunas temperatura e umidade. Linhas em que as duas estão nulas não têm utilidade, mas linhas com só uma delas nula devem ser mantidas. Qual código PySpark atende?

✓ Resposta: C) df.na.drop("all", subset=["temperatura", "umidade"])

Por quê: na.drop aceita "any" (padrão: remove a linha se alguma coluna avaliada for nula) ou "all" (remove só se todas forem nulas). O parâmetro subset limita as colunas avaliadas.

Dica de prova: Remover só quando todas as colunas indicadas forem nulas = na.drop("all", subset=[...]).

Referência: PySpark basics: valores nulos

Questão 8 de 12Databricks Intelligence Platform

Na Corretora Prisma, cerca de 40 analistas executam consultas SQL ad hoc em tabelas Delta ao longo do dia, com picos imprevisíveis. A equipe quer partida em poucos segundos, escala rápida quando há fila de consultas e custo baixo nos períodos ociosos. Qual computação atende melhor?

✓ Resposta: C) SQL warehouse serverless, com partida rápida e Intelligent Workload Management

Por quê: Databricks SQL oferece warehouses serverless, pro e classic. O serverless reúne Photon, Predictive IO e Intelligent Workload Management e é indicado para BI, análise exploratória e ETL com demanda variável.

Dica de prova: Consultas SQL concorrentes com picos e partida rápida = SQL warehouse serverless.

Referência: Tipos de SQL warehouse

Questão 9 de 12Governança e segurança

A auditoria da Rede Bancária Confiança quer consultar com SQL quem acessou ou alterou objetos do Unity Catalog e quando, a partir de uma tabela de sistema. Qual tabela usar?

Dica de prova: Quem fez o quê e quando = system.access.audit.

Questão 11 de 12Ingestão e carga de dados

Uma analista da Imobiliária Casa Nova recebeu de um parceiro um arquivo CSV de 300 MB e está com ele no próprio computador. Ela quer disponibilizá-lo no Unity Catalog para depois criar uma tabela e vai usar Add or upload data > Upload files to a volume. Quais privilégios ela precisa para concluir o upload?

✓ Resposta: C) WRITE VOLUME no volume de destino, USE SCHEMA no esquema e USE CATALOG no catálogo

Por quê: Volumes do Unity Catalog guardam arquivos não tabulares e arquivos para ingestão. Pela interface, o upload aceita arquivos de até 5 GB; depois é possível criar uma tabela gerenciada a partir do arquivo (o que exige CREATE TABLE e um SQL warehouse em execução).

Dica de prova: Upload para volume = WRITE VOLUME + USE SCHEMA + USE CATALOG.

Referência: Trabalhar com arquivos em volumes do Unity Catalog

Questão 12 de 12Solução de problemas, monitoramento e otimização

No job de seis tarefas da Agroindústria Vale Verde, a tarefa 4 falhou por uma credencial expirada; as tarefas 1 a 3 tiveram sucesso e as tarefas 5 e 6 dependem da 4. Depois de renovar a credencial, como recuperar a execução sem refazer o que já deu certo?

✓ Resposta: A) Usar Repair run, que reexecuta a tarefa que falhou e as tarefas que dependem dela

Por quê: O repair está disponível para jobs com duas ou mais tarefas. Cada tarefa reexecutada começa do zero, por isso é importante que as tarefas sejam idempotentes (overwrite ou MERGE em vez de append). Se havia job cluster compartilhado, o repair cria um novo cluster com sufixo _v1.

Dica de prova: Falha no meio de um job multitarefa = Repair run (só falhas e dependentes).

Referência: Solucionar e reparar falhas de jobs
