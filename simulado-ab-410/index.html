Questão 1 · Criar aplicativos inteligentes

A Gráfica Papel Nobre já tem uma tabela Orçamento no Dataverse com milhares de registros. O maker quer gerar rapidamente um app de tela responsivo, já conectado a essa tabela, para começar a ajustar. Qual caminho usar?

  1. Start with data > Create new data e descrever a tabela Orçamento ao Copilot
  2. Start with data > Upload file com um Excel exportado da tabela Orçamento
  3. Start with data > Dataverse, escolher a tabela Orçamento e Create app
  4. Create > Create from blank e montar as telas sem nenhuma fonte de dados
Ver resposta comentada

Resposta: C) Start with data > Dataverse, escolher a tabela Orçamento e Create app

Resposta correta: Start with data > Dataverse, escolher a tabela Orçamento e Create app

Por quê: Start with data oferece criar o app a partir de uma tabela existente do Dataverse, criar dados novos (com o designer ou o Copilot) ou carregar Excel/CSV. Para dados que já estão no Dataverse, escolha a tabela existente.

Dica de prova: Tabela já no Dataverse + app rápido = Start with data > Dataverse > Create app.

Referência: Criar app de tela com o Dataverse

Questão 2 · Criar lógica de aplicativo de negócios e automação

A Logística Porto Seguro tem um fluxo da nuvem que, para cada pedido aprovado, atualiza o sistema de estoque por um conector, cria a nota no Dataverse e envia a confirmação ao cliente; ele roda cerca de 300 vezes por dia. Quando qualquer uma dessas ações falha ou expira, a equipe quer registrar o erro numa lista do SharePoint, avisar o responsável no Teams e encerrar a execução marcada como falha, para aparecer corretamente no histórico. Hoje cada ação tem seu próprio Configure run after, o que deixou o fluxo grande e difícil de manter, e alguns erros escapam sem registro. Qual desenho o maker deve adotar?

  1. Criar uma ramificação paralela com as ações de registro e aviso para rodar junto com o processo
  2. Adicionar uma condição depois de cada ação comparando o status com Succeeded antes de seguir
  3. Configurar a política de repetição exponencial em cada ação e remover todo o Configure run after
  4. Agrupar as ações num escopo Try e criar um escopo Catch que rode quando o Try falhar
Ver resposta comentada

Resposta: D) Agrupar as ações num escopo Try e criar um escopo Catch que rode quando o Try falhar

Resposta correta: Agrupar as ações num escopo Try e criar um escopo Catch que rode quando o Try falhar

Por quê: Configure run after define se uma ação roda após sucesso, falha, tempo esgotado ou ação pulada. Escopos aplicam isso a grupos de ações, formando o padrão try/catch; Terminate encerra com o status desejado.

Dica de prova: Tratamento de erro centralizado = escopos Try e Catch com run after.

Referência: Tratamento de erros robusto

Questão 3 · Criar uma base para aplicativos inteligentes

Na Construtora Base Sólida, a coluna Data de Entrega da Obra foi criada com o formato Date only e o comportamento User local. Engenheiros em Manaus e em São Paulo veem, para a mesma obra, datas que diferem em um dia. A data não tem hora e não depende de fuso horário. O que ajustar?

  1. Pedir que todos os engenheiros usem o mesmo fuso nas opções pessoais
  2. Mudar o comportamento da coluna para Date only, uma alteração feita uma vez
  3. Mudar o formato da coluna para Date and time, mantendo o User local
  4. Excluir a coluna e recriá-la como texto no formato dia, mês e ano
Ver resposta comentada

Resposta: B) Mudar o comportamento da coluna para Date only, uma alteração feita uma vez

Resposta correta: Mudar o comportamento da coluna para Date only, uma alteração feita uma vez

Por quê: Colunas de data e hora têm comportamento (User local, Date only, Time zone independent) e formato. A Microsoft orienta evitar o formato Date only com o comportamento User local. Ao mudar o comportamento, os valores já gravados continuam em UTC e podem precisar de conversão.

Dica de prova: Mesma data em todos os fusos = comportamento Date only (mudança única).

Referência: Comportamento e formato de colunas de data e hora

Questão 4 · Criar aplicativos inteligentes

Na Metalúrgica Brasa Viva, o formulário com a coluna Salário só foi atribuído à função RH, e os demais usuários abrem um formulário sem essa coluna. Mesmo assim, alguns gestores conseguem ver salários numa exibição e ao exportar para o Excel. Como proteger a coluna de fato?

  1. Remover a coluna Salário das exibições públicas e manter o formulário atribuído só à função RH
  2. Criar uma regra de negócios que esconda a coluna Salário em todos os formulários dos gestores
  3. Atribuir a função RH também ao formulário de criação rápida da tabela que contém o salário
  4. Habilitar a segurança da coluna Salário e conceder Read a quem precisa por perfil de segurança de coluna
Ver resposta comentada

Resposta: D) Habilitar a segurança da coluna Salário e conceder Read a quem precisa por perfil de segurança de coluna

Resposta correta: Habilitar a segurança da coluna Salário e conceder Read a quem precisa por perfil de segurança de coluna

Por quê: Formulários por função de segurança controlam a experiência, não o acesso aos dados. Para coluna sensível, use segurança de coluna com perfis; quem não está em um perfil vê o valor mascarado, com o ícone de cadeado.

Dica de prova: Proteger o dado da coluna = perfil de segurança de coluna, não formulário.

Referência: Segurança em nível de coluna

Questão 5 · Criar lógica de aplicativo de negócios e automação

Na Empresa de Saneamento Água Limpa, os fluxos da nuvem de uma solução serão importados nos ambientes de teste e de produção. A equipe quer que, na importação, o administrador informe uma vez as conexões de cada ambiente e que os fluxos sejam ativados automaticamente, sem editar ação por ação. O que os fluxos devem usar?

  1. Referências de conexão da solução em vez de conexões diretas
  2. Conexões pessoais do maker compartilhadas com a equipe de operação
  3. Ações HTTP com credenciais fixas no lugar dos conectores padrão
  4. Variáveis de ambiente com usuário e senha das contas de serviço
Ver resposta comentada

Resposta: A) Referências de conexão da solução em vez de conexões diretas

Resposta correta: Referências de conexão da solução em vez de conexões diretas

Por quê: A referência de conexão é um componente de solução que aponta para uma conexão de um conector. Fluxos criados dentro de soluções usam referências; fluxos trazidos de fora continuam com conexões até serem atualizados (o verificador de fluxo sugere a troca).

Dica de prova: Fluxo que muda de ambiente sem edição: referências de conexão na solução.

Referência: Usar referências de conexão

Questão 6 · Criar uma base para aplicativos inteligentes

A Transportadora Vale do Aço tem uma solução gerenciada em produção. Na nova versão, a equipe retirou da solução uma coluna e um formulário que não serão mais usados e quer que eles também desapareçam do ambiente de produção na importação. Como deve ser feita a implantação?

  1. Criar um patch da solução sem os componentes e importar o patch em produção
  2. Exportar a nova versão como gerenciada e importar com a ação Upgrade
  3. Importar a nova versão com a ação Update, que substitui a versão anterior
  4. Exportar a nova versão como não gerenciada e importá-la sobre a gerenciada
Ver resposta comentada

Resposta: B) Exportar a nova versão como gerenciada e importar com a ação Upgrade

Resposta correta: Exportar a nova versão como gerenciada e importar com a ação Upgrade

Por quê: Para remover um componente gerenciado do destino, retire-o da solução no desenvolvimento, exporte como gerenciada com versão maior e importe com Upgrade. Update é mais rápido, mas deixa os componentes antigos; patches nunca excluem.

Dica de prova: Componente removido da solução precisa sumir do destino: Upgrade (Update mantém, patch não exclui).

Referência: Atualizar uma solução

Questão 8 · Criar lógica de aplicativo de negócios e automação

Um maker da Cooperativa de Saúde Vida Ativa criou um conector personalizado para a API REST interna de agendamentos e o usou em um app de tela. Outros makers precisam do mesmo conector em fluxos da nuvem, mas não o encontram na lista de conectores. O que ele deve fazer?

  1. Exportar a definição OpenAPI e pedir que cada maker recrie o conector do zero
  2. Compartilhar a própria conexão do maker para que todos usem a mesma credencial da API
  3. Certificar o conector na Microsoft para que ele apareça a todos os usuários do ambiente
  4. Compartilhar o conector com os makers, que depois criam as próprias conexões a ele
Ver resposta comentada

Resposta: D) Compartilhar o conector com os makers, que depois criam as próprias conexões a ele

Resposta correta: Compartilhar o conector com os makers, que depois criam as próprias conexões a ele

Por quê: No Power Apps e no Power Automate, conectores personalizados ficam visíveis só para o autor até serem compartilhados. Também são compartilhados ao compartilhar um app ou criar um fluxo de equipe que os usa; a certificação é para uso fora da organização.

Dica de prova: Conector personalizado para colegas = compartilhar o conector; certificação é para fora da organização.

Questão 9 · Criar uma base para aplicativos inteligentes

Na Transportadora Rota Certa, usuários com a função Conferente leem e editam linhas de Inspeção e de Veículo, mas recebem erro de privilégio ao escolher um Veículo na pesquisa do formulário de Inspeção. A tabela Inspeção tem uma coluna de pesquisa para Veículo. Que privilégios faltam à função?

  1. Assign na tabela Inspeção e Share na tabela Veículo relacionado
  2. Create na tabela Veículo e Delete na tabela Inspeção
  3. Append na tabela Inspeção e Append To na tabela Veículo
  4. Append To na tabela Inspeção e Append na tabela Veículo
Ver resposta comentada

Resposta: C) Append na tabela Inspeção e Append To na tabela Veículo

Resposta correta: Append na tabela Inspeção e Append To na tabela Veículo

Por quê: Para preencher uma coluna de pesquisa, o usuário precisa de Append na tabela que contém a pesquisa e de Append To na tabela referenciada, além de Read. Em relacionamentos N:N, é preciso Append nas duas tabelas.

Dica de prova: Preencher pesquisa: Append na tabela que tem a pesquisa, Append To na tabela apontada.

Referência: Privilégios Append e Append To

Questão 11 · Criar lógica de aplicativo de negócios e automação

A Distribuidora de Autopeças Roda Firme tem um fluxo da nuvem agendado que, toda noite, percorre cerca de 60 mil linhas de Estoque no Dataverse e chama, para cada linha, uma API de preços por um conector personalizado, gravando o resultado. O fluxo pertence a um analista com licença Power Automate Premium. Nas últimas semanas, as execuções ficaram muito lentas, com respostas 429 em várias ações, e a TI confirmou que a causa é o volume de solicitações do próprio fluxo, não uma falha da API. A gerência quer manter o processo noturno, dar ao fluxo uma capacidade própria de solicitações, independente de quem o possui, e cortar chamadas desnecessárias. O que deve ser recomendado?

  1. Comprar um pacote Power Platform requests add-on e atribuí-lo diretamente ao fluxo
  2. Atribuir uma licença Process ao fluxo, em solução, e processar só as linhas alteradas
  3. Desativar a política de repetição das ações para não repetir chamadas com erro 429
  4. Dividir o fluxo em vários fluxos iguais do mesmo analista, todos rodando ao mesmo tempo
Ver resposta comentada

Resposta: B) Atribuir uma licença Process ao fluxo, em solução, e processar só as linhas alteradas

Resposta correta: Atribuir uma licença Process ao fluxo, em solução, e processar só as linhas alteradas

Por quê: Cada ação de um fluxo conta como solicitação da Power Platform, inclusive repetições e paginação. Quando um fluxo específico é limitado (respostas 429), a recomendação é atribuir a ele uma licença Process (ou a um grupo de fluxos) e otimizar o desenho para reduzir chamadas.

Dica de prova: Fluxo de alto volume limitado com 429 = licença Process no fluxo e menos chamadas.

Referência: Limites e alocações de solicitações

Questão 12 · Criar uma base para aplicativos inteligentes

Na Corretora de Seguros Proteção Total, a tabela Apólice precisa de uma coluna Segurado que aceite tanto uma conta (empresa) quanto um contato (pessoa física), em um único campo de pesquisa no formulário. Que tipo de coluna usar?

  1. Duas colunas de pesquisa simples e uma regra que oculte a não usada
  2. Uma coluna Escolha com os nomes de todas as contas e de todos os contatos
  3. Uma coluna do tipo Customer, que referencia uma conta ou um contato da base
  4. Uma pesquisa multitabela personalizada criada no designer do Power Apps
Ver resposta comentada

Resposta: C) Uma coluna do tipo Customer, que referencia uma conta ou um contato da base

Resposta correta: Uma coluna do tipo Customer, que referencia uma conta ou um contato da base

Por quê: O Dataverse tem pesquisas especiais: Customer (conta ou contato), Owner (usuário ou equipe), Regarding (várias tabelas em atividades) e PartyList (várias referências, criadas pelo sistema). Para conta ou contato no mesmo campo, a opção nativa é Customer.

Dica de prova: Conta ou contato em um só campo = coluna Customer (pesquisa polimórfica).

Referência: Tipos de pesquisa no Dataverse
