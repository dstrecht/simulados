Questão 1 · Domínio 1: Ingestão e transformação de dados

A equipe de controladoria de uma construtora domina SQL, mas não programa em Python. Ela precisa criar, em um job visual do AWS Glue Studio, regras de transformação com junções, filtros e expressões CASE sobre dados de obras e fornecedores. O que permite que a equipe escreva essa lógica sem aprender PySpark?

  1. Converter o job em Python shell e chamar consultas SQL a partir da biblioteca pandas
  2. Criar views no Amazon Athena e agendar um crawler para materializá-las no job
  3. Escrever a lógica em um script Bash executado pelo job antes da etapa de leitura
  4. Adicionar ao job visual o transform SQL Query e escrever a lógica em Spark SQL
Ver resposta comentada

Resposta: D) Adicionar ao job visual o transform SQL Query e escrever a lógica em Spark SQL

Resposta correta: Adicionar ao job visual o transform SQL Query e escrever a lógica em Spark SQL

Por quê: Em engenharia de dados, a linguagem acompanha a equipe e o motor: o Glue Studio oferece o transform SQL Query, que executa Spark SQL sobre um ou mais nós de entrada. Assim, a lógica fica em SQL, mas roda no Spark distribuído do Glue.

Dica de prova: Equipe SQL dentro de job visual do Glue: transform SQL Query (Spark SQL).

Referência: AWS Glue Studio: transform SQL Query

Questão 2 · Domínio 2: Gerenciamento do armazenamento de dados

Um aplicativo de streaming de música guarda sessões de usuários em uma tabela do Amazon DynamoDB, e cada sessão deve sumir 24 horas depois do último acesso. Hoje um job noturno faz scan e apaga os itens vencidos, consumindo muita capacidade de escrita. A equipe quer remover os itens sem custo de escrita e sem código. O que deve ser feito?

  1. Ativar o TTL com um atributo String que guarda a data de expiração no formato ISO 8601
  2. Trocar o job noturno por uma Lambda acionada pelo DynamoDB Streams a cada atualização
  3. Criar um índice secundário global com a data de expiração e consultar os itens vencidos
  4. Ativar o TTL com um atributo Number que guarda o horário de expiração em epoch segundos
Ver resposta comentada

Resposta: D) Ativar o TTL com um atributo Number que guarda o horário de expiração em epoch segundos

Resposta correta: Ativar o TTL com um atributo Number que guarda o horário de expiração em epoch segundos

Por quê: O Time to Live (TTL) do DynamoDB exclui itens depois do horário indicado em um atributo do tipo Number em formato epoch (segundos). As exclusões são feitas pelo serviço, geralmente em poucos dias após a expiração, sem consumir capacidade de escrita.

Dica de prova: Expirar itens do DynamoDB sem custo de escrita = TTL com atributo Number em epoch segundos.

Referência: Amazon DynamoDB: Time to Live

Questão 3 · Domínio 3: Operações e suporte de dados

Uma state machine do AWS Step Functions do tipo Express processa milhões de eventos de cliques por dia. Algumas execuções terminam com erro, mas a equipe não encontra no console nem pela API o histórico dessas execuções para depurar. O que deve ser feito?

  1. Habilitar o logging da state machine no CloudWatch Logs, com nível ERROR ou ALL
  2. Alterar o tipo da state machine para Standard nas configurações existentes
  3. Ativar data events do AWS CloudTrail para registrar a entrada de cada estado
  4. Chamar GetExecutionHistory, que guarda as execuções Express por até 90 dias
Ver resposta comentada

Resposta: A) Habilitar o logging da state machine no CloudWatch Logs, com nível ERROR ou ALL

Resposta correta: Habilitar o logging da state machine no CloudWatch Logs, com nível ERROR ou ALL

Por quê: Workflows Express são feitos para alto volume e duram até 5 minutos, com cobrança por execução e duração. Diferentemente do Standard, cujo histórico fica disponível por 90 dias, o Step Functions não guarda o histórico das execuções Express: é preciso habilitar o logging no CloudWatch Logs para depurar.

Dica de prova: Express = alto volume, até 5 minutos, sem histórico nativo: habilite CloudWatch Logs. Standard = até 1 ano, histórico de 90 dias.

Referência: AWS Step Functions: Standard x Express

Questão 4 · Domínio 4: Segurança e governança de dados

Durante uma investigação, um auditor externo exige prova de que os arquivos de log do AWS CloudTrail entregues no Amazon S3 não foram alterados nem excluídos depois da entrega. Qual recurso fornece essa evidência?

  1. Validação de integridade dos arquivos de log, com arquivos digest assinados
  2. Versionamento do S3 no bucket, guardando as versões anteriores dos arquivos
  3. Criptografia SSE-KMS dos arquivos com uma chave gerenciada pelo cliente
  4. CloudTrail Insights, que detecta atividade fora do padrão nas chamadas de API
Ver resposta comentada

Resposta: A) Validação de integridade dos arquivos de log, com arquivos digest assinados

Resposta correta: Validação de integridade dos arquivos de log, com arquivos digest assinados

Por quê: A log file integrity validation usa hash SHA-256 e assinatura digital (SHA-256 com RSA). Os arquivos digest referenciam os logs da hora anterior e encadeiam os digests anteriores, o que permite detectar alteração, exclusão ou inclusão indevida de arquivos de log.

Dica de prova: Provar que log de auditoria não foi adulterado: validação de integridade do CloudTrail (arquivos digest).

Referência: AWS CloudTrail: validação de integridade dos arquivos de log

Questão 5 · Domínio 1: Ingestão e transformação de dados

Uma varejista com sede em Nova York precisa iniciar um workflow do AWS Step Functions às 6h no horário local, diariamente, também depois das mudanças de horário de verão. Hoje uma regra agendada do Amazon EventBridge com expressão cron dispara uma hora antes ou depois em parte do ano. Qual solução resolve com o menor esforço operacional?

  1. Configurar a regra com a expressão rate(1 day) a partir das 6h para acompanhar o horário de verão
  2. Substituir a regra por um trigger agendado do AWS Glue com cron em UTC que inicia o workflow
  3. Criar um agendamento no EventBridge Scheduler com o fuso America/New_York na expressão cron
  4. Manter a regra agendada e criar uma função Lambda que reescreve o cron em UTC duas vezes por ano
Ver resposta comentada

Resposta: C) Criar um agendamento no EventBridge Scheduler com o fuso America/New_York na expressão cron

Resposta correta: Criar um agendamento no EventBridge Scheduler com o fuso America/New_York na expressão cron

Por quê: O EventBridge Scheduler permite schedules cron e one-time em qualquer fuso do banco de dados IANA e ajusta automaticamente ao horário de verão. Regras agendadas tradicionais do EventBridge avaliam cron em UTC.

Dica de prova: Agendamento no horário local com horário de verão: EventBridge Scheduler com time zone.

Referência: EventBridge Scheduler: tipos de agendamento e fusos

A empresa quer receber os arquivos direto no Amazon S3, sem pedir que os parceiros troquem de protocolo ou de cliente e sem administrar servidores. Qual solução atende?

  2. Criar um servidor SFTP gerenciado no AWS Transfer Family usando o Amazon S3 como armazenamento
  3. Instalar o agente do AWS DataSync em cada laboratório para enviar os arquivos ao bucket do S3
  4. Publicar uma API no Amazon API Gateway que receba os arquivos e os grave no bucket do Amazon S3

Resposta: B) Criar um servidor SFTP gerenciado no AWS Transfer Family usando o Amazon S3 como armazenamento

Resposta correta: Criar um servidor SFTP gerenciado no AWS Transfer Family usando o Amazon S3 como armazenamento

Por quê: O AWS Transfer Family cria servidores gerenciados para SFTP, FTPS, FTP e AS2, com armazenamento no Amazon S3 ou no EFS. Parceiros continuam usando os mesmos clientes e scripts, e a empresa deixa de administrar servidores de transferência.

Questão 7 · Domínio 3: Operações e suporte de dados

Um job Spark em um cluster do Amazon EMR falha em algumas tarefas com a mensagem Container killed by YARN for exceeding memory limits. Os executores usam pouco heap da JVM, mas o consumo fora do heap (buffers de rede e bibliotecas nativas) é alto. Qual ajuste trata a causa?

  1. Aumentar o número de partições do HDFS do cluster
  2. Diminuir spark.executor.memoryOverhead para liberar heap
  3. Ativar a compressão do shuffle com o codec LZ4
  4. Aumentar spark.executor.memoryOverhead dos executores
Ver resposta comentada

Resposta: D) Aumentar spark.executor.memoryOverhead dos executores

Resposta correta: Aumentar spark.executor.memoryOverhead dos executores

Por quê: No Spark sobre YARN, o contêiner de cada executor recebe spark.executor.memory (heap) mais spark.executor.memoryOverhead (memória fora do heap). Quando o uso total excede o limite, o YARN mata o contêiner. A correção é aumentar o overhead, reduzir núcleos por executor ou usar instâncias com mais memória; no EMR, a configuração é feita pela classificação spark-defaults.

Dica de prova: Container killed by YARN for exceeding memory limits: aumente spark.executor.memoryOverhead.

Referência: Amazon EMR: configurar o Spark

Questão 8 · Domínio 4: Segurança e governança de dados

Um job do AWS Glue usa uma role com a política gerenciada AmazonS3FullAccess, mas só precisa ler o prefixo bruto/vendas/ do bucket lake-prod e gravar no prefixo curado/vendas/ do mesmo bucket. Uma auditoria pediu menor privilégio. Qual mudança atende?

  1. Política AmazonS3FullAccess mantida, com SCP negando a exclusão de objetos no bucket lake-prod
  2. Política gerenciada AWSGlueServiceRole, que já limita o acesso do job aos buckets do Glue
  3. Política gerenciada AmazonS3ReadOnlyAccess somada a uma bucket policy que libere a gravação
  4. Política customizada com GetObject no prefixo bruto e PutObject no prefixo curado
Ver resposta comentada

Resposta: D) Política customizada com GetObject no prefixo bruto e PutObject no prefixo curado

Resposta correta: Política customizada com GetObject no prefixo bruto e PutObject no prefixo curado

Por quê: Quando políticas gerenciadas da AWS dão acesso amplo demais, crie políticas customizadas com ações e recursos específicos: s3:GetObject em arn:aws:s3:::lake-prod/bruto/vendas/*, s3:PutObject em arn:aws:s3:::lake-prod/curado/vendas/* e s3:ListBucket no bucket com condição s3:prefix. Isso aplica o princípio do menor privilégio.

Dica de prova: Política gerenciada ampla demais: política customizada com ações mínimas e ARNs de prefixo.

Referência: Amazon S3: exemplos de políticas baseadas em identidade

Questão 9 · Domínio 1: Ingestão e transformação de dados

Um hospital recebe resultados de exames em um stream do Amazon Data Firehose que entrega no Amazon S3. Antes da entrega, o CPF de cada registro deve ser substituído por um hash, e registros de teste devem ser descartados. Cada registro é tratado de forma independente, sem relação com os anteriores. Qual solução é mais simples?

  1. Criar um job de streaming do AWS Glue com janelas de 15 minutos que reescreve os registros após a entrega no S3
  2. Ativar a transformação de dados do Firehose com uma função Lambda que devolve cada registro como Ok ou Dropped
  3. Criar uma aplicação no Managed Service for Apache Flink com estado por paciente para mascarar e filtrar os registros
  4. Ativar o particionamento dinâmico do Firehose com uma expressão jq que calcula o hash e remove os registros de teste
Ver resposta comentada

Resposta: B) Ativar a transformação de dados do Firehose com uma função Lambda que devolve cada registro como Ok ou Dropped

Resposta correta: Ativar a transformação de dados do Firehose com uma função Lambda que devolve cada registro como Ok ou Dropped

Por quê: Transformações stateless, que olham apenas para o registro atual (mascarar, normalizar, filtrar), cabem na transformação de dados do Amazon Data Firehose com Lambda. Processamentos stateful, como janelas e agregações por chave, pedem motores com estado, como o Apache Flink.

Dica de prova: Mascarar ou filtrar registro a registro antes da entrega do Firehose: Lambda de transformação (Ok/Dropped).

Referência: Amazon Data Firehose: parâmetros da transformação

  2. Ativar o SageMaker ML Lineage Tracking para os jobs do Airflow on-premises

Resposta: D) Enviar os eventos OpenLineage ao SageMaker Catalog pela API PostLineageEvent

Resposta correta: Enviar os eventos OpenLineage ao SageMaker Catalog pela API PostLineageEvent

Por quê: Além da captura automática de fontes como AWS Glue e Amazon Redshift, a linhagem do SageMaker Unified Studio aceita eventos de sistemas externos pela API PostLineageEvent, que recebe um run event no formato OpenLineage. Questão 11 · Domínio 3: Operações e suporte de dados

Uma regra do Amazon EventBridge envia a um tópico do Amazon SNS os eventos de falha de jobs do AWS Glue. O e-mail chega com o JSON completo do evento, difícil de ler pela equipe de plantão. A equipe quer uma mensagem curta com o nome do job, o estado e o horário, sem criar código. O que configurar?

  1. Filtro de assinatura no SNS para remover campos do evento original
  2. Input transformer no alvo da regra, com input paths e um template de texto
  3. Função Lambda entre a regra e o SNS para montar o texto da mensagem de e-mail
  4. Archive do barramento para resumir os eventos antes do envio
Ver resposta comentada

Resposta: B) Input transformer no alvo da regra, com input paths e um template de texto

Resposta correta: Input transformer no alvo da regra, com input paths e um template de texto

Por quê: O input transformer do EventBridge personaliza o que é enviado ao alvo: o input path map extrai valores do evento em variáveis e o input template monta o texto ou JSON final. É útil para mensagens legíveis no SNS ou para adaptar o formato esperado por um alvo, sem código.

Dica de prova: Mudar o formato do evento entregue ao alvo do EventBridge sem código: input transformer.

Referência: Amazon EventBridge: input transformation

Questão 12 · Domínio 4: Segurança e governança de dados

Um banco prepara no AWS Glue DataBrew um dataset de transações para cientistas de dados. O número da conta deve ficar ilegível para eles, mas precisa continuar permitindo junções entre arquivos, e a equipe de fraude, com acesso à chave, deve conseguir recuperar o valor original. Qual transformação do DataBrew atende?

  1. CRYPTOGRAPHIC_HASH com chave guardada no AWS Secrets Manager
  2. SHUFFLE_ROWS embaralhando os números de conta entre as linhas
  3. DETERMINISTIC_ENCRYPT com chave guardada no AWS Secrets Manager
  4. MASK_CUSTOM substituindo todos os dígitos pelo caractere #, sem chave
Ver resposta comentada

Resposta: C) DETERMINISTIC_ENCRYPT com chave guardada no AWS Secrets Manager

Resposta correta: DETERMINISTIC_ENCRYPT com chave guardada no AWS Secrets Manager

Por quê: O DataBrew tem etapas de receita para PII: mascaramento, hash criptográfico, criptografia probabilística e criptografia determinística, usando chaves guardadas no Secrets Manager. A determinística preserva igualdade (junções, GROUP BY) e é reversível com a chave; o hash preserva igualdade mas é irreversível.

Dica de prova: Pseudonimizar mantendo junções e com reversão por quem tem a chave: criptografia determinística. Sem reversão: hash.

Referência: AWS Glue DataBrew: identificar e tratar dados pessoais (PII)
