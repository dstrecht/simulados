Questão 1 de 12Conceitos de segurança, conformidade e identidade

Qual tipo de criptografia usa a mesma chave para cifrar e decifrar os dados?

✓ Resposta: C) Criptografia simétrica

Por quê: A criptografia simétrica é rápida e usa uma chave compartilhada. A assimétrica usa chave pública para cifrar e privada para decifrar, e é base de assinaturas digitais.

Dica de prova: Mesma chave nos dois lados: simétrica.

Referência: Microsoft Learn: criptografia

Questão 9 de 12Conceitos de segurança, conformidade e identidade

Por que se adiciona um salt antes de gerar o hash de uma senha?

✓ Resposta: C) Para que senhas iguais tenham hashes distintos

Por quê: Sem salt, senhas iguais têm o mesmo hash, o que facilita ataques com tabelas pré-calculadas (rainbow tables).

Dica de prova: Salt: mesma senha, hash diferente.

Resumo por domínio e pegadinhas da Security, Compliance and Identity SC-900

Como a prova pensa

O SC-900 é uma prova de fundamentos que testa se você reconhece o produto ou recurso Microsoft certo para um cenário curto de negócio. A maioria das perguntas tem quatro alternativas que são produtos reais, quase sempre de áreas diferentes (Entra, Defender, Sentinel, Purview), e a errada mais tentadora é um recurso vizinho do mesmo produto. Há também questões de múltipla resposta (Escolha DUAS) e perguntas de diferença entre conceitos em que uma alternativa tem os papéis invertidos. O peso maior está em soluções de segurança (35% a 40%) e no Microsoft Entra (25% a 30%), então reconhecer rapidamente qual Defender, qual recurso do Sentinel e qual recurso do Entra se aplica decide a nota.

Conceitos de segurança, conformidade e identidade (10-15% da prova)

É o menor domínio (10% a 15%), mas é a base de tudo e costuma ter questões diretas, de definição.

  • Armadilha: Cifrar com a chave privada do remetente para que só o destinatário leia. Como evitar: A privada do remetente assina. Sigilo para o destinatário = chave pública do destinatário.
  • Armadilha: Verificar assinatura digital com a chave privada ou assinar com a pública. Como evitar: Assina com a privada do remetente; verifica com a pública dele.
  • Gatilho: se o enunciado traz “mesma chave nos dois lados”, pense em: Criptografia simétrica.
  • Gatilho: se o enunciado traz “hash publicado para conferir o arquivo baixado”, pense em: Integridade.

Recursos do Microsoft Entra (25-30% da prova)

  • Armadilha: Dar a função de Administrador de Segurança (ou Global) a quem só precisa redefinir senhas de usuários comuns. Como evitar: Menor privilégio: Administrador de Assistência Técnica. Administrador de Segurança mexe em configurações de segurança e Global tem acesso total.
  • Armadilha: Escolher a proteção de senha quando o cenário pede que o usuário troque a própria senha esquecida. Como evitar: Proteção de senha só bloqueia senhas fracas; quem redefine é o SSPR. E FIDO2 elimina a senha, mas não bloqueia termos em quem ainda usa senha.
  • Gatilho: se o enunciado traz “consumidores criam conta com e-mail ou conta social”, pense em: Microsoft Entra External ID para clientes (CIAM).
  • Gatilho: se o enunciado traz “admin só quando precisa, por tempo limitado, com aprovação”, pense em: PIM (atribuição qualificada).

Recursos das soluções de segurança da Microsoft (35-40% da prova)

Este é o domínio mais pesado (35% a 40%) e o mais largo: segurança de rede do Azure (NSG, Azure Firewall, WAF, DDoS Protection, Bastion, Key Vault), Microsoft Defender for Cloud (CSPM e planos CWP), Microsoft Sentinel (SIEM e SOAR) e Microsoft Defender XDR com seus produtos (Ponto de Extremidade…

  • Armadilha: Escolher o NSG para bloquear injeção de SQL ou XSS porque ele filtra tráfego. Como evitar: O NSG filtra por IP, porta e protocolo e não inspeciona HTTP. Ataques de aplicação web pedem WAF.
  • Armadilha: Escolher o Azure Firewall Premium para ataques volumétricos de negação de serviço. Como evitar: O Azure Firewall filtra tráfego, mas a proteção dedicada contra DDoS volumétrico é o Azure DDoS Protection.
  • Gatilho: se o enunciado traz “Kerberoasting, pass-the-hash, golden ticket, controladores de domínio”, pense em: Microsoft Defender para Identidade.
  • Gatilho: se o enunciado traz “conta falsa isca no AD”, pense em: Conta honeytoken (Defender para Identidade).

Recursos das soluções de conformidade da Microsoft (20-25% da prova)

Este domínio (20% a 25%) é todo Microsoft Purview, mais os compromissos de privacidade da Microsoft: Service Trust Portal, Compliance Manager, classificação de dados, rótulos de confidencialidade, DLP, retenção e gerenciamento de registros, Insider Risk, conformidade de comunicações, barreiras de…

  • Armadilha: Achar que o rótulo de confidencialidade define o tempo de guarda e o de retenção protege o acesso. Como evitar: Os papéis estão invertidos: confidencialidade = quem acessa; retenção = quanto tempo fica. Os dois são do Purview, não do Defender nem do Sentinel.
  • Armadilha: Escolher Reter indefinidamente ou Excluir após o uso para guardar por três anos e depois apagar. Como evitar: Guardar X anos e apagar depois é reter e depois excluir.
  • Gatilho: se o enunciado traz “relatórios ISO 27001 e SOC 2 dos serviços da Microsoft”, pense em: Service Trust Portal.
  • Gatilho: se o enunciado traz “pontuação de conformidade com LGPD ou ISO e ações de melhoria”, pense em: Compliance Manager (avaliação a partir de modelo).

Erros que mais custam pontos

  • Confundir recursos vizinhos: revisões de acesso x PIM, regras de automação x playbooks, política x rótulo de retenção, NSG x Azure Firewall x WAF.
  • Trocar Microsoft Secure Score (Microsoft 365), classificação de segurança do Defender for Cloud e pontuação de conformidade do Compliance Manager.
  • Marcar a alternativa com conceitos invertidos por ler rápido (risco de entrada x usuário, qualificada x ativa, chave pública x privada, confidencialidade x retenção).
  • Atribuir a um Defender o recurso de outro: sensores em controladores de domínio são do Defender para Identidade, ASR é do Ponto de Extremidade, shadow IT é do Cloud Apps.
