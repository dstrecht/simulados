Questão 1 · Gerenciar memória, estado e execução

Uma equipe nota que agentes aplicam regras de validação diferentes conforme a sessão, porque cada pessoa cola as regras no prompt. Seguindo a tabela de fonte da verdade do Learn, onde essas regras de validação devem morar?

  1. Na descrição de cada issue
  2. No histórico de chat da equipe
  3. Nos logs do último workflow run
  4. Nas instruções do repositório
Ver resposta comentada

Resposta: D) Nas instruções do repositório

Resposta correta: Nas instruções do repositório

Por quê: Fonte da verdade única: requisitos na issue; decisões no PR ou na documentação; regras de validação nas instruções do repositório; resultados nos logs e artefatos de workflow.

Dica de prova: Regra de validação: instruções do repositório.

Referência: Learn: estratégias de memória do agente

Questão 2 · Implementar guardrails e responsabilização

A Fundação Saber quer supervisão humana nos agentes sem travar a entrega. Em quais pontos o Learn recomenda colocar humanos?

  1. Nos pontos de decisão, como merge, deploy e acesso a segredos
  2. Na escolha do modelo e na redação de cada mensagem de commit
  3. Em cada passo, inclusive análise, formatação e checks de rotina
  4. Na leitura de arquivos e nas buscas que o agente faz no código
Ver resposta comentada

Resposta: A) Nos pontos de decisão, como merge, deploy e acesso a segredos

Resposta correta: Nos pontos de decisão, como merge, deploy e acesso a segredos

Por quê: Human-in-the-loop no Learn é seletivo: humanos nos pontos de decisão (merge, deploy, acesso a segredo), não em cada passo como análise, formatação ou checks de rotina.

Dica de prova: Humano no merge, no deploy e no segredo.

Referência: Learn: human-in-the-loop

Questão 3 · Implementar o uso de ferramentas e a interação com o ambiente

Um desenvolvedor da Agência Pixel configurou o GitHub MCP server remoto na IDE com um PAT em vez de OAuth. Que limites de acesso passam a valer para o servidor?

  1. O acesso somente leitura ao repositório atual, igual ao token padrão do cloud agent
  2. Os escopos concedidos ao PAT, sujeitos às restrições de PAT definidas pela organização
  3. Os escopos aprovados no login OAuth, que continuam valendo mesmo com o PAT configurado
  4. O acesso de administrador da organização, já que o PAT contorna as políticas de Copilot
Ver resposta comentada

Resposta: B) Os escopos concedidos ao PAT, sujeitos às restrições de PAT definidas pela organização

Resposta correta: Os escopos concedidos ao PAT, sujeitos às restrições de PAT definidas pela organização

Por quê: No GitHub MCP server remoto, OAuth limita aos escopos aprovados no login; com PAT, valem os escopos do token e as restrições de PAT configuradas pela organização.

Dica de prova: PAT no MCP: escopos do token mais restrições da org.

Referência: GitHub Docs: configurar o GitHub MCP server

Questão 4 · Orquestrar a coordenação multiagente

  1. Um comentário automático pedindo ao agente para revisar o próprio diff
  2. Um rótulo de conflito aplicado pelos revisores quando notarem o aviso no PR
  3. Um job agendado semanal que lista os PRs abertos há mais de sete dias

Resposta correta: Um passo com git merge --no-commit do main, marcado como required check

Questão 5 · Preparar a arquitetura de agentes e os processos do SDLC

Uma equipe separou um agente de planejamento e escreveu no prompt dele que não deve editar arquivos. Mesmo assim, ele alterou código em uma sessão. Qual ajuste o Learn recomenda para impor essa fronteira?

  1. Pedir ao agente que confirme no plano que não vai editar nada
  2. Adicionar a proibição também no arquivo de instruções do repositório
  3. Restringir o agente a ferramentas de leitura por allowlist de tools
  4. Repetir a proibição em letras maiúsculas no início do prompt
Ver resposta comentada

Resposta: C) Restringir o agente a ferramentas de leitura por allowlist de tools

Resposta correta: Restringir o agente a ferramentas de leitura por allowlist de tools

Por quê: O Learn resume: trate instruções de não editar como orientação e allowlists de ferramentas e gates como enforcement. Agente de planejamento fica só com ferramentas de leitura.

Dica de prova: Instrução orienta; allowlist de tools impõe.

Referência: Learn: separar planejamento e execução

Questão 6 · Realizar avaliação, análise de erros e ajuste

Uma empresa vai delegar a um agente a troca da biblioteca de criptografia de um serviço de pagamentos. Além do resultado esperado, o contrato da tarefa precisa trazer restrições operacionais. Qual item é uma restrição operacional típica, segundo o Learn?

  1. Não alterar workflows sem revisão da plataforma nem fazer push no main
  2. Concluir a tarefa no menor tempo, sem esperar os checks obrigatórios
  3. Abrir o pull request com o maior número possível de melhorias extras
  4. Usar o modelo mais recente disponível para gerar o código da troca
Ver resposta comentada

Resposta: A) Não alterar workflows sem revisão da plataforma nem fazer push no main

Resposta correta: Não alterar workflows sem revisão da plataforma nem fazer push no main

Por quê: No contrato de tarefa do Learn, as entradas trazem contexto, escopo e restrições (sem mudanças em workflows sem revisão da plataforma, sem novos segredos, sem push direto no main); as saídas são plano, PR e evidências; os critérios de sucesso são checks, sinal de segurança resolvido e escopo coerente.

Dica de prova: Restrição operacional: o que o agente não pode fazer no caminho.

Referência: Learn: entradas, saídas e critérios de sucesso

Questão 7 · Gerenciar memória, estado e execução

Um artefato de workflow do agente da Clínica Horizonte contém dados que não deveriam estar lá, e a equipe vai excluí-lo pela aba Actions. O que precisa ser considerado antes?

  1. A exclusão vale só na interface; o artefato segue no download pela API
  2. O artefato volta após 90 dias, quando o ciclo de retenção padrão reinicia
  3. Só o dono da organização exclui artefatos, mediante chamado ao suporte
  4. Artefatos excluídos não podem ser restaurados, então a evidência some de vez
Ver resposta comentada

Resposta: D) Artefatos excluídos não podem ser restaurados, então a evidência some de vez

Resposta correta: Artefatos excluídos não podem ser restaurados, então a evidência some de vez

Por quê: Na poda de memória, o Learn lembra que artefatos podem ser apagados manualmente pela aba Actions e que artefatos excluídos não podem ser restaurados; por isso, avalie antes o impacto na trilha de evidências.

Dica de prova: Artefato apagado não volta.

Referência: Learn: estado durável e context drift

Questão 8 · Implementar guardrails e responsabilização

O copilot-setup-steps.yml de um repositório herda as permissões padrão do GITHUB_TOKEN, que na organização são de leitura e escrita. O time de segurança quer reduzir o que essa preparação de ambiente pode fazer. Qual ajuste o guia de guardrails recomenda?

  1. Declarar no job as permissões mínimas, como contents: read
  2. Remover o job de preparação e instalar tudo durante a sessão
  3. Trocar o GITHUB_TOKEN por um PAT de admin guardado em secret
  4. Mover os steps de preparação para o prompt do custom agent
Ver resposta comentada

Resposta: A) Declarar no job as permissões mínimas, como contents: read

Resposta correta: Declarar no job as permissões mínimas, como contents: read

Por quê: O guia de guardrails do cloud agent pede revisar as permissões padrão do GITHUB_TOKEN usadas no copilot-setup-steps.yml e impor o mínimo necessário nos arquivos de workflow; permissions é uma das chaves que o job copilot-setup-steps aceita.

Dica de prova: Setup steps com token amplo: permissions mínimas no job.

Referência: GitHub Docs: guardrails do cloud agent

Questão 10 · Orquestrar a coordenação multiagente

Uma semana depois de um run de agentes, o time quer entender por que o agente de testes marcou um falso positivo, mas os logs ao vivo já não ajudam. Onde está a principal fonte de evidência para essa análise post-hoc?

  1. Na lista de branches excluídos nas configurações do repositório
  2. Na seção Artifacts do resumo do run, baixando o relatório
  3. Nos comentários de revisão de outros PRs do repositório
  4. No histórico do chat da IDE de quem disparou o workflow
Ver resposta comentada

Resposta: B) Na seção Artifacts do resumo do run, baixando o relatório

Resposta correta: Na seção Artifacts do resumo do run, baixando o relatório

Por quê: Para analisar o comportamento depois da execução, o Learn indica abrir o workflow run na aba Actions, localizar a seção Artifacts e baixar o artefato, como agent-report, mesmo quando os logs estão incompletos.

Dica de prova: Análise post-hoc: baixe os artefatos do run.

Referência: Learn: observabilidade multiagente

Questão 11 · Preparar a arquitetura de agentes e os processos do SDLC

Um agente corrigiu um PR depois de o check integration-tests falhar, e o mesmo check falhou de novo na segunda tentativa. Pela política de iteração segura do Learn, qual é o próximo passo?

  1. Repetir as correções até o check passar, sem limite de tentativas
  2. Escalar a um humano com falha, tentativas, evidência e próximo passo
  3. Tirar o check da lista de obrigatórios até o agente estabilizar
  4. Fechar o PR e abrir outro idêntico para recomeçar o histórico
Ver resposta comentada

Resposta: B) Escalar a um humano com falha, tentativas, evidência e próximo passo

Resposta correta: Escalar a um humano com falha, tentativas, evidência e próximo passo

Por quê: Política de iteração: se um check obrigatório falha, o agente pode revisar o branch e reexecutar; se o mesmo check falha duas vezes, ele escala para um humano com o que falhou, o que foi tentado, a evidência e o próximo passo sugerido.

Dica de prova: Mesmo check falhou duas vezes: escale.

Referência: Learn: operação e controles de agentes

Questão 12 · Realizar avaliação, análise de erros e ajuste

Um time escreveu revisao.instructions.md com checklists destinados ao Copilot code review. Desde então, os PRs abertos pelo cloud agent trazem esses checklists no corpo. Como manter o arquivo valendo só para a revisão?

  1. Mover as regras para o AGENTS.md da raiz do repositório
  2. Adicionar excludeAgent: cloud-agent ao frontmatter
  3. Copiar as regras para o prompt do cloud agent
  4. Trocar o applyTo para abranger o repo inteiro
Ver resposta comentada

Resposta: B) Adicionar excludeAgent: cloud-agent ao frontmatter

Resposta correta: Adicionar excludeAgent: cloud-agent ao frontmatter

Por quê: Arquivos .instructions.md aceitam excludeAgent com os valores code-review ou cloud-agent, para que um desses agentes não use aquelas instruções.

Dica de prova: Instrução só para o code review: excludeAgent: cloud-agent.

Referência: GitHub Docs: instruções de repositório
