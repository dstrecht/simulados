Questão 1 · Implementar uma estratégia de instrumentação

O time de produto da Startup Saúde em Casa usa GitHub Projects e quer criar um gráfico salvo com o andamento das tarefas de uma iteração, filtrado por um rótulo, que todos que veem o projeto possam consultar. Qual caminho usar?

  1. Exportar os itens para CSV e montar o gráfico em uma planilha compartilhada pela equipe
  2. Abrir o gráfico Pulse do repositório e filtrar pelo rótulo da iteração atual do projeto
  3. Abrir os insights do projeto, clicar em New chart, aplicar filtros e salvar
  4. Criar um workflow do Actions que gere um PNG do gráfico e anexe a imagem em uma issue fixada
Ver resposta comentada

Resposta: C) Abrir os insights do projeto, clicar em New chart, aplicar filtros e salvar

Resposta correta: Abrir os insights do projeto, clicar em New chart, aplicar filtros e salvar

Por quê: Insights for Projects permite criar e configurar gráficos atuais e históricos a partir dos itens do projeto, com filtros e agrupamentos.

Dica de prova: Gráfico de itens do GitHub Projects: insights > New chart > filtros > Save changes.

Referência: GitHub Projects: criar gráficos

O escritório de projetos da Seguradora Valente mantém dezenas de consultas salvas no Azure Boards, como Bugs críticos abertos e Itens bloqueados por equipe, que servem de base para indicadores mensais de qualidade e de fluxo. O coordenador quer que o GitHub Copilot, conectado ao servidor MCP remoto do Azure DevOps, execute essas consultas existentes e resuma os resultados em linguagem natural, sem que ninguém precise reescrever as consultas. Ele também leu que existe uma ferramenta para executar WIQL arbitrário e quer saber se pode usá-la desde já sem configuração adicional. Qual orientação está correta?

  1. Reescrever cada consulta em WIQL, já que o servidor só executa consultas digitadas no prompt pelo usuário final
  2. Exportar as consultas para Excel e anexar os arquivos no chat, pois o servidor não acessa consultas salvas
  3. Usar a ferramenta search_workitem para cada consulta, já que ela executa WIQL salvo e não exige configuração

Questão 4 · Projetar e implementar um plano de segurança e conformidade

A Corretora Valor Real habilitou o code scanning do GitHub Advanced Security for Azure DevOps com a configuração padrão. Agora precisa varrer também um serviço escrito em Go e analisar branches de release, não só a branch padrão. O que fazer?

  1. Adotar a configuração avançada, com as tarefas do CodeQL no próprio pipeline
  2. Ligar a push protection, que analisa o código de todas as branches enviadas
  3. Manter a configuração padrão e ajustar o agendamento para rodar de hora em hora
  4. Habilitar o dependency scanning, que também cobre falhas no código em Go
Ver resposta comentada

Resposta: A) Adotar a configuração avançada, com as tarefas do CodeQL no próprio pipeline

Resposta correta: Adotar a configuração avançada, com as tarefas do CodeQL no próprio pipeline

Por quê: Code scanning no Azure DevOps tem configuração padrão (automática, só branch padrão, sem pipeline) e avançada (tarefas CodeQL no pipeline, várias branches, build personalizado).

Dica de prova: Precisa de outras branches, Go ou build customizado: code scanning em configuração avançada.

Referência: GitHub Advanced Security for Azure DevOps: code scanning

Questão 5 · Projetar e implementar uma estratégia de controle do código-fonte

No repositório da Mobilidade Urbana Via Rápida, a main é alvo de duas rulesets: a da organização exige uma aprovação em pull requests e a do repositório exige duas aprovações. Também existe uma regra de proteção de branch antiga exigindo uma aprovação. Quantas aprovações um PR para a main precisa?

  1. Uma, pois a regra de proteção de branch substitui as rulesets que miram a mesma branch
  2. Uma, pois a ruleset da organização tem prioridade sobre a ruleset definida no repositório
  3. Quatro, pois as aprovações exigidas em cada regra são somadas para chegar ao total
  4. Duas, pois as regras se agregam e vale a versão mais restritiva entre rulesets e proteção de branch
Ver resposta comentada

Resposta: D) Duas, pois as regras se agregam e vale a versão mais restritiva entre rulesets e proteção de branch

Resposta correta: Duas, pois as regras se agregam e vale a versão mais restritiva entre rulesets e proteção de branch

Por quê: Várias rulesets podem atingir a mesma branch; as regras se somam em camadas e a mais restritiva prevalece, inclusive frente a proteções de branch.

Dica de prova: Rulesets em camadas: vale a regra mais restritiva, sem prioridade entre elas.

Referência: GitHub: sobre rulesets

Questão 7 · Projetar e implementar pipelines de build e lançamento

A equipe da Loja de Móveis Encanto usa swap com preview no App Service. Ao iniciar o swap do slot de staging para produção, ela percebe que a operação pausa no meio. O que acontece nessa primeira fase e por que é útil?

  1. O staging é desligado e religado em produção, pausando até a próxima janela de manutenção
  2. O conteúdo de produção é copiado para o staging para servir de backup antes da troca
  3. As configurações do slot de produção são aplicadas ao staging e o swap pausa para validação
  4. O tráfego de produção é dividido meio a meio entre os slots até alguém concluir a troca manual
Ver resposta comentada

Resposta: C) As configurações do slot de produção são aplicadas ao staging e o swap pausa para validação

Resposta correta: As configurações do slot de produção são aplicadas ao staging e o swap pausa para validação

Por quê: Swap com preview (multifase) aplica as configurações do destino na origem e pausa; depois a equipe conclui ou cancela o swap.

Dica de prova: Validar com configurações de produção antes de trocar: swap com preview.

Referência: App Service: slots de implantação

Questão 9 · Projetar e implementar um plano de segurança e conformidade

Scripts de automação da Construtora Pilar usam um PAT global do Azure DevOps válido para várias organizações. O time de segurança soube que esse tipo de token está sendo descontinuado. Qual é a orientação atual da Microsoft?

  1. Trocar o PAT global por um PAT com escopo Full access em cada organização
  2. Renovar o PAT global com validade de um ano, que continua aceito para automações
  3. Guardar o PAT global no Key Vault, o que evita a descontinuação do token
  4. Migrar para tokens do Entra ou PATs de organização com escopos mínimos
Ver resposta comentada

Resposta: D) Migrar para tokens do Entra ou PATs de organização com escopos mínimos

Resposta correta: Migrar para tokens do Entra ou PATs de organização com escopos mínimos

Por quê: PATs devem ser o último recurso: prefira Microsoft Entra, identidades gerenciadas ou entidades de serviço; se usar PAT, com escopo de organização, mínimos privilégios e vida curta.

Dica de prova: PAT global do Azure DevOps: aposentado; migre para Entra ou PAT de organização com escopo mínimo.

Referência: Azure DevOps: personal access tokens
