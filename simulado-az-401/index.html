Questão 1 de 12 · Implementar uma estratégia de instrumentação

O time de produto da Startup Saúde em Casa usa GitHub Projects e quer criar um gráfico salvo com o andamento das tarefas de uma iteração, filtrado por um rótulo, que todos que veem o projeto possam consultar. Qual caminho usar?

Resposta: C) Abrir os insights do projeto, clicar em New chart, aplicar filtros e salvar

Por quê: Insights for Projects permite criar e configurar gráficos atuais e históricos a partir dos itens do projeto, com filtros e agrupamentos.

Dica de prova: Gráfico de itens do GitHub Projects: insights > New chart > filtros > Save changes.

Referência: GitHub Projects: criar gráficos

Questão 2 de 12 · Projetar e implementar pipelines de build e lançamento

No pipeline de infraestrutura da Energia Solar Nascente, os aprovadores querem ver, antes da aprovação, quais recursos serão criados, alterados ou excluídos pela implantação do arquivo Bicep, sem que nada seja modificado no Azure. O que incluir no estágio anterior à aprovação?

Resposta: D) A operação what-if do Azure Resource Manager sobre o arquivo Bicep

Por quê: O what-if do ARM mostra criação, alteração e exclusão previstas antes de implantar um Bicep, com as mesmas permissões exigidas pela implantação.

Dica de prova: Prever mudanças de Bicep sem aplicar: what-if.

Referência: Bicep: operação what-if

Questão 3 de 12 · Projetar e implementar processos e comunicações

O escritório de projetos da Seguradora Valente mantém dezenas de consultas salvas no Azure Boards, como Bugs críticos abertos e Itens bloqueados por equipe, que servem de base para indicadores mensais de qualidade e de fluxo. O coordenador quer que o GitHub Copilot, conectado ao servidor MCP remoto do Azure DevOps, execute essas consultas existentes e resuma os resultados em linguagem natural, sem que ninguém precise reescrever as consultas. Ele também leu que existe uma ferramenta para executar WIQL arbitrário e quer saber se pode usá-la desde já sem configuração adicional. Qual orientação está correta?

Resposta: D) Usar a ferramenta wit_query com a ação get_results nas consultas salvas; wit_query_by_wiql exige o cabeçalho X-MCP-Insiders

Por quê: As ferramentas de work item do MCP do Azure DevOps cobrem itens, comentários, revisões, backlogs e consultas salvas; algumas ferramentas, como wit_query_by_wiql, exigem Insiders.

Dica de prova: Executar consulta salva pelo MCP do Azure DevOps: wit_query get_results.

Referência: Azure DevOps: servidor MCP remoto

Questão 4 de 12 · Projetar e implementar um plano de segurança e conformidade

A Corretora Valor Real habilitou o code scanning do GitHub Advanced Security for Azure DevOps com a configuração padrão. Agora precisa varrer também um serviço escrito em Go e analisar branches de release, não só a branch padrão. O que fazer?

Resposta: A) Adotar a configuração avançada, com as tarefas do CodeQL no próprio pipeline

Por quê: Code scanning no Azure DevOps tem configuração padrão (automática, só branch padrão, sem pipeline) e avançada (tarefas CodeQL no pipeline, várias branches, build personalizado).

Dica de prova: Precisa de outras branches, Go ou build customizado: code scanning em configuração avançada.

Referência: GitHub Advanced Security for Azure DevOps: code scanning

Questão 5 de 12 · Projetar e implementar uma estratégia de controle do código-fonte

No repositório da Mobilidade Urbana Via Rápida, a main é alvo de duas rulesets: a da organização exige uma aprovação em pull requests e a do repositório exige duas aprovações. Também existe uma regra de proteção de branch antiga exigindo uma aprovação. Quantas aprovações um PR para a main precisa?

Resposta: D) Duas, pois as regras se agregam e vale a versão mais restritiva entre rulesets e proteção de branch

Por quê: Várias rulesets podem atingir a mesma branch; as regras se somam em camadas e a mais restritiva prevalece, inclusive frente a proteções de branch.

Dica de prova: Rulesets em camadas: vale a regra mais restritiva, sem prioridade entre elas.

Referência: GitHub: sobre rulesets

Clientes da Livraria Página Viva reclamam de lentidão ao finalizar a compra. O time quer ver uma requisição específica de ponta a ponta, com o tempo gasto em cada dependência. Qual recurso usar?

Dica de prova: Ver uma requisição por todos os serviços com tempos: detalhes de transação de ponta a ponta.

Questão 7 de 12 · Projetar e implementar pipelines de build e lançamento

A equipe da Loja de Móveis Encanto usa swap com preview no App Service. Ao iniciar o swap do slot de staging para produção, ela percebe que a operação pausa no meio. O que acontece nessa primeira fase e por que é útil?

Resposta: C) As configurações do slot de produção são aplicadas ao staging e o swap pausa para validação

Por quê: Swap com preview (multifase) aplica as configurações do destino na origem e pausa; depois a equipe conclui ou cancela o swap.

Dica de prova: Validar com configurações de produção antes de trocar: swap com preview.

Referência: App Service: slots de implantação

Questão 8 de 12 · Projetar e implementar processos e comunicações

Na Agro Cerrado, o Copilot cloud agent falha com frequência porque precisa de um SDK específico e de dependências privadas que não existem no ambiente padrão. A equipe quer que essas ferramentas já estejam instaladas antes de o agente começar a trabalhar. Qual configuração resolve?

Resposta: A) Criar o copilot-setup-steps.yml na branch padrão, com um único job copilot-setup-steps que instala o SDK

Por quê: O ambiente do Copilot cloud agent roda no GitHub Actions e pode ser preparado pelo copilot-setup-steps.yml (job copilot-setup-steps, na branch padrão) para instalar ferramentas e dependências.

Dica de prova: Preinstalar ferramentas para o cloud agent: copilot-setup-steps.yml na branch padrão.

Referência: Copilot cloud agent: configurar o ambiente de desenvolvimento

Questão 9 de 12 · Projetar e implementar um plano de segurança e conformidade

Scripts de automação da Construtora Pilar usam um PAT global do Azure DevOps válido para várias organizações. O time de segurança soube que esse tipo de token está sendo descontinuado. Qual é a orientação atual da Microsoft?

Resposta: D) Migrar para tokens do Entra ou PATs de organização com escopos mínimos

Por quê: PATs devem ser o último recurso: prefira Microsoft Entra, identidades gerenciadas ou entidades de serviço; se usar PAT, com escopo de organização, mínimos privilégios e vida curta.

Dica de prova: PAT global do Azure DevOps: aposentado; migre para Entra ou PAT de organização com escopo mínimo.

Referência: Azure DevOps: personal access tokens

Questão 10 de 12 · Projetar e implementar uma estratégia de controle do código-fonte

A Montadora Eixo Forte vai migrar repositórios do Azure DevOps Services para o GitHub Enterprise Cloud com o GitHub Enterprise Importer e quer avisar as equipes sobre o que será levado. Além do código Git com o histórico de commits, o que a ferramenta migra?

Resposta: A) Pull requests, histórico e anexos dos PRs, vínculos de itens nos PRs e políticas de branch do repositório

Por quê: O GEI migra repositórios do Azure DevOps Cloud (não do Server) com PRs e políticas de branch; LFS, Boards e Pipelines ficam fora e são tratados à parte.

Dica de prova: GEI a partir do Azure DevOps: código, PRs e políticas de branch; sem Boards, Pipelines e LFS.

Referência: GitHub: migrações do Azure DevOps para o GitHub

Questão 12 de 12 · Projetar e implementar pipelines de build e lançamento

A equipe de plataforma da Rede Atacadista Grão quer que outros feeds da organização usem seu feed Comum como upstream source, consumindo os pacotes publicados e os já salvos de origens públicas. Qual configuração do feed Comum é necessária?

Resposta: B) Visibilidade para membros da organização ou do Microsoft Entra ID, compartilhando a view @Local
