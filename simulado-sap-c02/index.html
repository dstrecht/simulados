Questão 1 de 12 · Aceleração da migração e da modernização de workloads

Uma instituição educacional está migrando rapidamente dezenas de aplicações web legadas para a AWS. A equipe de arquitetura deseja padronizar a criação de redes, contas, pipelines de CI/CD e padrões de observabilidade, minimizando retrabalho e garantindo que novos times possam provisionar ambientes de forma consistente e segura. Qual combinação de serviços e abordagens é MAIS apropriada para acelerar essa migração e modernização, mantendo boas práticas de arquitetura?

Resposta: D) Usar o Control Tower para contas e guardrails, o Service Catalog para blueprints de rede e aplicação e pipelines padronizados no CodePipeline

Por quê: Esta alternativa é a mais adequada porque combina serviços voltados especificamente para aceleração e padronização de migração em escala. O AWS Control Tower facilita a criação e governança de múltiplas contas com guardrails e boas práticas de segurança. O AWS Service Catalog, apoiado por AWS CloudFormation, permite publicar blueprints padronizados de redes (VPC, sub-redes, segurança) e de aplicações, que podem ser reutilizados por diferentes times.

Dica de prova: Para migração e modernização em escala, pense em três pilares: (1) Governança multi-conta (AWS Organizations, Control Tower), (2) Infraestrutura como código e catálogos padronizados (CloudFormation, Service Catalog) e (3) Pipelines de CI/CD reutilizáveis (CodePipeline, CodeBuild, CodeDeploy).

Questão 2 de 12 · Design de novas soluções

Uma empresa de mídia digital deseja lançar uma nova plataforma de distribuição de vídeos sob demanda (VoD) em múltiplas regiões da AWS. Os requisitos incluem: (1) baixa latência global para streaming, (2) alta disponibilidade e resiliência a falhas regionais, (3) capacidade de personalizar recomendações de conteúdo por usuário, (4) minimização de esforço operacional na camada de backend, e (5) custos previsíveis para o ambiente de produção. Como um Solutions Architect deve projetar a solução principal de backend para atender a esses requisitos?

Resposta: C) Usar API Gateway e Lambda para a lógica, DynamoDB global tables para metadados e perfis, CloudFront com origem no S3 para o streaming HLS e DASH e failover entre regiões pelo Route 53 com health checks

Por quê: Esta alternativa atende simultaneamente aos requisitos de baixa latência global, alta disponibilidade multi-região, personalização por usuário e baixo esforço operacional. O uso de Amazon CloudFront com S3 garante distribuição global de conteúdo estático e streaming com baixa latência. A combinação de API Gateway + Lambda fornece uma camada de aplicação serverless, reduzindo a necessidade de gerenciar servidores e oferecendo escalabilidade automática.

Dica de prova: Para requisitos de baixa latência global + alta disponibilidade + pouco esforço operacional, pense primeiro em: CloudFront para distribuição, S3 para conteúdo estático, DynamoDB global tables para dados multi-região e arquiteturas serverless (API Gateway + Lambda) para lógica de aplicação.

Referência: Building Fault-Tolerant Applications on AWS

Questão 4 de 12 · Soluções de design de complexidade organizacional

Uma organização governamental com múltiplos departamentos autônomos utiliza AWS Organizations com várias contas para isolar workloads, mas enfrenta dificuldades em padronizar o uso de serviços e manter a conformidade com normas internas. Cada departamento tem sua própria conta, com equipes de TI independentes, e a diretoria de tecnologia quer minimizar esforço operacional centralizado, mantendo ainda assim governança forte. Como o arquiteto de soluções deve projetar a governança na AWS para atender a esses requisitos?

Resposta: B) Manter as várias contas no Organizations, com SCPs por OU limitando serviços e regiões, e Config e Control Tower para a conformidade

Por quê: Esta alternativa é a mais adequada porque preserva o modelo de múltiplas contas, que é uma boa prática para isolamento de workloads e limites de segurança, e adiciona governança centralizada por meio de AWS Organizations. O uso de Service Control Policies (SCPs) em nível de Unidade Organizacional (OU) permite restringir quais serviços e regiões podem ser utilizados, alinhando-se às normas internas.

Dica de prova: Para exames de nível profissional, sempre que o cenário envolver múltiplas contas, requisitos de conformidade e necessidade de padronização com pouco esforço operacional, pense em uma combinação de AWS Organizations (SCPs), AWS Control Tower, AWS Config e CloudTrail organizacional.

Questão 5 de 12 · Aceleração da migração e da modernização de workloads

Uma empresa de mídia digital possui centenas de aplicações Java legadas executando em VMs on-premises, cada uma com configurações de servidor de aplicações ligeiramente diferentes. O board aprovou um programa agressivo de migração em 9 meses, com objetivo de reduzir custos operacionais e padronizar a plataforma, mas sem reescrever as aplicações neste primeiro ciclo. A equipe de TI quer minimizar mudanças de código, acelerar a movimentação em massa e, ao mesmo tempo, criar uma base que facilite modernizações futuras para serviços gerenciados e arquitetura de microsserviços. Como um arquiteto de soluções deve projetar a abordagem inicial de migração para atender a esses requisitos?

Resposta: A) Containerizar as aplicações Java com o App2Container no ECS com Fargate e usar o Migration Hub para priorizar o portfólio, deixando a refatoração de código para depois

Por quê: Esta alternativa é a mais adequada porque combina aceleração de migração com modernização incremental. O uso do AWS App2Container permite containerizar aplicações Java legadas sem exigir reescrita de código, padronizando o runtime de servidores de aplicação. Ao executar esses containers em Amazon ECS com AWS Fargate, a empresa elimina a gestão de servidores, reduz custos operacionais e cria uma base pronta para futuras modernizações (como decomposição em microsserviços ou adoção de outros serviços gerenciados).

Dica de prova: Para acelerar migração e modernização de aplicações Java/.NET legadas, priorize abordagens de containerização assistida (como AWS App2Container) combinadas com orquestração gerenciada (ECS/EKS) e camadas serverless (Fargate).

Questão 6 de 12 · Design de novas soluções

Uma aplicação sem servidor com milhares de execuções AWS Lambda simultâneas passou a esgotar as conexões de um banco Amazon RDS for MySQL, com erros intermitentes. Qual solução reduz o problema com a menor mudança na aplicação?

Resposta: A) Usar o Amazon RDS Proxy para agrupar e reutilizar as conexões das funções

Por quê: Funções Lambda escalam rapidamente e podem abrir muitas conexões. O RDS Proxy é o componente gerenciado indicado para esse cenário.

Dica de prova: Lambda esgotando conexões do RDS: RDS Proxy.

Referência: Amazon RDS Proxy

Questão 8 de 12 · Soluções de design de complexidade organizacional

Uma empresa de manufatura com várias subsidiárias ao redor do mundo utiliza múltiplas contas AWS, gerenciadas por diferentes equipes regionais. Cada região criou suas próprias políticas SCP, funções IAM e configurações de AWS CloudTrail e AWS Config, resultando em falta de padronização, dificuldades de auditoria e riscos de segurança. A diretoria quer: (1) padronizar a governança e segurança em todas as contas, (2) manter alguma autonomia operacional por região, (3) reduzir o esforço para criação de novas contas e (4) garantir trilha de auditoria centralizada. Como o arquiteto de soluções deve projetar a solução de forma mais adequada?

Resposta: D) Organizar OUs por região e ambiente com SCPs padronizadas, centralizar CloudTrail e Config em uma conta de segurança e usar o Control Tower para padronizar contas novas

Por quê: Esta alternativa é a mais adequada porque usa o AWS Organizations para criar uma hierarquia de OUs, permitindo padronizar governança e segurança via SCPs e, ao mesmo tempo, manter autonomia operacional por região e ambiente. A centralização de logs de AWS CloudTrail e AWS Config em uma conta de segurança dedicada garante auditoria consistente e separação de deveres.

Dica de prova: Para cenários com múltiplas contas e requisitos de conformidade, pense em: (1) AWS Organizations + OUs para governança, (2) SCPs para limites de segurança, (3) conta central de segurança/logs e (4) ferramentas como AWS Control Tower ou Account Factory para padronizar a criação de contas.

Questão 10 de 12 · Design de novas soluções

Uma empresa de análise de dados quer projetar uma nova solução em AWS para processar grandes volumes de dados de logs de aplicativos gerados continuamente. Os logs devem ser ingeridos em tempo quase real, armazenados de forma econômica para análises históricas e disponibilizados para consultas ad-hoc por analistas usando SQL. A empresa deseja minimizar o esforço operacional e evitar gerenciar servidores. Qual arquitetura atende melhor a esses requisitos?

Resposta: C) Utilizar Amazon Data Firehose para ingerir e entregar os dados diretamente em tabelas externas no Amazon Athena, armazenando os arquivos brutos comprimidos no Amazon S3.

Por quê: Esta alternativa é a mais adequada porque utiliza serviços totalmente gerenciados e serverless para cumprir todos os requisitos. O Amazon Data Firehose oferece ingestão de dados em tempo quase real com entrega automática e escalável, sem necessidade de gerenciar servidores. Ele pode entregar dados diretamente no Amazon S3 em formato comprimido (por exemplo, GZIP ou Parquet), permitindo armazenamento econômico e durável.

Dica de prova: Para pipelines de logs e eventos em tempo quase real com baixa administração, pense em Amazon Data Firehose + S3 + Athena. Firehose simplifica ingestão e entrega; S3 fornece armazenamento barato e durável; Athena oferece consultas SQL serverless sobre dados em S3.

Questão 11 de 12 · Otimização contínua

Uma empresa de SaaS possui uma aplicação crítica em produção com arquitetura multi-AZ em uma única região da AWS. Após uma revisão de arquitetura, o time de soluções identificou que, embora a aplicação seja resiliente a falhas de AZ, ainda existe risco de indisponibilidade em caso de falha regional. Como o arquiteto de soluções deve melhorar continuamente essa solução para aumentar a resiliência, mantendo o impacto mínimo na operação atual e permitindo validações periódicas do plano de recuperação?

Resposta: A) Adotar ativo-ativo em duas regiões com o Global Accelerator, replicação assíncrona dos dados e game days regulares de falha regional

Por quê: Esta alternativa é a melhor abordagem de melhoria contínua para este cenário, pois adiciona resiliência em nível de região e mantém a operação em produção com impacto controlado. Uma arquitetura ativa-ativa multi-região, combinada com AWS Global Accelerator ou Amazon Route 53 para direcionamento de tráfego, reduz significativamente o RTO e o RPO, permitindo que a aplicação continue atendendo usuários mesmo em caso de falha completa de uma região.

Dica de prova: Para workloads críticos, pense em camadas de resiliência: primeiro multi-AZ, depois multi-região. Em melhoria contínua, procure sempre adicionar mecanismos de teste (game days, simulações de falha) ao invés de apenas documentar planos.

Questão 12 de 12 · Soluções de design de complexidade organizacional

Uma organização global está padronizando o uso de AWS Organizations para gerenciar dezenas de contas AWS pertencentes a diferentes unidades de negócio. O time de arquitetura quer aplicar políticas centralizadas que imponham requisitos mínimos de segurança (como proibição de desativar CloudTrail e uso obrigatório de chaves KMS gerenciadas pela organização), mas também precisa permitir que cada unidade de negócio tenha autonomia para criar políticas adicionais mais restritivas quando necessário. Qual abordagem de design atende melhor a esses requisitos?

Resposta: C) Usar uma hierarquia de OUs, com SCPs de controles mínimos no topo e SCPs mais restritivas das unidades em OUs filhas

Por quê: Esta alternativa é a mais adequada porque usa o modelo recomendado pela AWS para ambientes multi-contas: uma hierarquia de OUs com Service Control Policies (SCPs) aplicadas em camadas. As SCPs nas OUs de nível superior definem a 'linha de base' de segurança (por exemplo, impedir desativação de CloudTrail, exigir uso de KMS gerenciado centralmente), enquanto as unidades de negócio podem anexar SCPs adicionais, mais restritivas, em OUs filhas ou diretamente nas contas.

Dica de prova: Pense nas SCPs como um "teto máximo de permissões" por OU ou conta. O ideal é usar uma OU raiz com políticas de baseline (segurança mínima obrigatória) e depois especializar por unidade de negócio com SCPs adicionais mais restritivas, nunca mais permissivas.
