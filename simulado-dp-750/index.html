Questão 1 de 12 · Configurar e ajustar um ambiente do Azure Databricks

A área comercial de uma rede de postos consulta um painel com o faturamento diário por região, calculado a partir de uma tabela de 3 bilhões de linhas. As consultas estão lentas, e os números podem ter até uma hora de atraso. A equipe quer resultados pré-calculados e atualizados de hora em hora, com o mínimo de código. O que você deve criar em um SQL warehouse serverless?

Resposta: C) CREATE MATERIALIZED VIEW fat_regiao SCHEDULE EVERY 1 HOUR AS SELECT regiao, data, sum(valor) AS total FROM vendas GROUP BY ALL

Por quê: Materialized views pré-calculam consultas caras e são atualizadas por agenda (SCHEDULE EVERY ou CRON), por TRIGGER ON UPDATE ou com REFRESH manual. No Databricks SQL, são criadas em SQL warehouse Pro ou serverless.

Dica de prova: Agregação cara com tolerância a atraso: materialized view com SCHEDULE.

Referência: CREATE MATERIALIZED VIEW

Questão 2 de 12 · Implantar e manter pipelines de dados e cargas de trabalho

Um job da Carteira Digital Moeda+ aplica uma UDF Python linha a linha para normalizar textos de 300 milhões de transações: tira acentos, deixa em minúsculas e remove espaços extras. O estágio é lento, e o Spark UI mostra executores perdidos por falta de memória no processo Python. O que você deve fazer primeiro?

Resposta: B) Reescrever a lógica com funções nativas do Spark, como lower, trim e translate

Por quê: UDFs Python processam linha a linha fora da JVM, com serialização e consumo extra de memória, e não são otimizadas pelo Catalyst nem aceleradas pelo Photon. Quando existe função nativa equivalente, prefira-a; se a UDF for inevitável, considere pandas UDFs vetorizadas.

Dica de prova: UDF Python lenta ou estourando memória: troque por funções nativas do Spark.

Referência: Funções definidas pelo usuário (UDFs)

Questão 3 de 12 · Preparar e processar dados

A Empresa de Telefonia Fala Brasil guarda 3 anos de registros de chamadas em arquivos CSV com 120 colunas. Os relatórios leem 6 colunas e filtram por data, mas cada consulta varre todos os arquivos inteiros e demora muito. A equipe quer reduzir a leitura e ter transações ACID nas cargas. Para qual formato você deve converter os dados?

Resposta: C) Tabela Delta gerenciada no Unity Catalog

Por quê: Formatos colunares (Parquet, e Delta sobre Parquet) leem só as colunas necessárias e usam estatísticas para pular dados. O Delta Lake acrescenta transações ACID e histórico e é o formato padrão de tabelas no Azure Databricks.

Dica de prova: Muitas colunas, poucas lidas e necessidade de ACID: Delta (Parquet colunar + log de transações).

Referência: O que é Delta Lake

Questão 4 de 12 · Proteger e governar objetos do Unity Catalog

O time de segurança da Companhia Aérea Voe Bem quer centralizar no Log Analytics, junto com os logs de outros recursos do Azure, os eventos de auditoria do workspace do Azure Databricks, inclusive o texto de cada comando executado em notebooks e das consultas enviadas aos SQL warehouses. O workspace já está no plano Premium. O que você deve configurar?

Resposta: D) Configurações de diagnóstico do workspace para o Log Analytics e verbose audit logs ativados

Por quê: No Azure Databricks, os logs de diagnóstico (plano Premium) são enviados pelas configurações de diagnóstico para Log Analytics, Event Hubs ou storage. Os verbose audit logs acrescentam eventos com o texto dos comandos (runCommand de notebooks e commandSubmit e commandFinish do Databricks SQL).

Dica de prova: Auditoria no Log Analytics: diagnostic settings; texto de comandos e consultas: verbose audit logs.

Referência: Habilitar verbose audit logs

Questão 5 de 12 · Configurar e ajustar um ambiente do Azure Databricks

A analista Bruna, da Rede de Restaurantes Sabor Caseiro, criou um Genie Agent sobre as tabelas de vendas, com um SQL warehouse serverless, e quer liberá-lo para os gerentes das lojas, que não têm permissão nesse warehouse. Cada gerente deve ver só os dados que já pode consultar no Unity Catalog. O que Bruna deve configurar?

Resposta: C) Compartilhar o Genie Agent com os gerentes como CAN RUN e garantir SELECT deles nas tabelas

Por quê: Genie Agents (antes Genie spaces) usam duas credenciais: a de computação, embutida por quem configurou o warehouse, e a de dados, que é sempre a do usuário final no Unity Catalog. Os consumidores precisam de CAN VIEW ou CAN RUN no agente e SELECT nos dados.

Dica de prova: Genie Agent: warehouse com credencial da autora; dados com o SELECT de cada usuário.

Referência: Criar e compartilhar um Genie Agent

Questão 6 de 12 · Implantar e manter pipelines de dados e cargas de trabalho

A Rede de Lojas Calçados Passo Firme mantém um notebook com MERGE manual para aplicar o CDC de estoque vindo do SQL Server. Os eventos às vezes chegam fora de ordem, as exclusões precisam ser aplicadas e a equipe gasta muito tempo mantendo a lógica de deduplicação e ordenação. Qual abordagem reduz o código e trata esses casos de forma declarativa?

Resposta: B) Migrar para AUTO CDC em pipeline declarativo, com KEYS, SEQUENCE BY e APPLY AS DELETE WHEN

Por quê: Quando a lógica de CDC (ordenação, exclusões, deduplicação) fica complexa em notebook, o pipeline declarativo com AUTO CDC substitui o MERGE manual e cuida de eventos fora de ordem pela coluna de sequência.

Dica de prova: MERGE manual de CDC difícil de manter: AUTO CDC com KEYS e SEQUENCE BY.

Referência: AUTO CDC em pipelines declarativos

Questão 7 de 12 · Preparar e processar dados

A Construtora Pilar mantém um data lake em Parquet puro gravado por jobs Spark. Leitores enxergam dados parciais quando um job falha no meio da gravação, a auditoria quer consultar a versão da tabela de obras da véspera e o time precisa aplicar upserts diários. Qual formato de tabela atende aos três requisitos?

Resposta: A) Delta Lake, com transações ACID, time travel e suporte a MERGE

Por quê: Delta Lake acrescenta ao Parquet um log de transações que fornece ACID, histórico de versões (time travel) e operações como MERGE, UPDATE e DELETE.

Dica de prova: ACID, versão anterior e upsert no mesmo requisito: Delta Lake.

Referência: O que é Delta Lake

Questão 8 de 12 · Proteger e governar objetos do Unity Catalog

Um job de uma fintech usa um cluster clássico cuja configuração Spark precisa da chave de acesso de um serviço externo, guardada no escopo de segredo kv-fin com o nome chave-api. A chave não pode aparecer em texto na definição do cluster. O que você deve escrever na configuração Spark?

Resposta: B) spark.servico.chave {{secrets/kv-fin/chave-api}}

Por quê: Referências a segredos na forma {{secrets/escopo/chave}} funcionam em propriedades Spark e variáveis de ambiente da computação. O usuário que configura precisa de permissão de leitura no escopo.

Dica de prova: Segredo em configuração Spark ou variável de ambiente: {{secrets/escopo/chave}}.

Referência: Usar segredos em configurações Spark e variáveis de ambiente

Questão 9 de 12 · Configurar e ajustar um ambiente do Azure Databricks

A Holding Grupo Vértice tem um metastore do Unity Catalog compartilhado pelos workspaces ws-dev, ws-hml e ws-prd. O catálogo prd_financeiro deve ser acessível a partir do ws-prd; mesmo usuários com SELECT concedido não podem consultá-lo do ws-dev. A auditoria também pede que o ws-hml enxergue o catálogo, mas apenas para leitura. O que você deve configurar?

Resposta: D) Workspace-catalog binding com ws-prd em leitura e escrita e ws-hml em leitura

Por quê: Por padrão, um catálogo é acessível de todos os workspaces ligados ao metastore. Com workspace-catalog binding, o owner ou quem tem MANAGE restringe o catálogo a workspaces específicos, com acesso de leitura e escrita ou somente leitura, isolando produção de desenvolvimento.

Dica de prova: Isolar catálogo de produção por workspace: workspace-catalog binding, com opção somente leitura.

Referência: Vinculação catálogo-workspace

Questão 10 de 12 · Implantar e manter pipelines de dados e cargas de trabalho

Um notebook orquestrador da Editora Saber precisa executar o notebook valida_lote passando o parâmetro data_ref, esperar no máximo 10 minutos e usar o texto devolvido pelo filho (OK ou REJEITADO) para decidir o próximo passo. Qual combinação atende?

Resposta: D) dbutils.notebook.run('valida_lote', 600, {'data_ref': d}) no pai e dbutils.notebook.exit('OK') no filho

Por quê: Use dbutils.notebook.run quando o pai precisa de parâmetros, tempo limite e valor de retorno (via dbutils.notebook.exit) ou de execução condicional. Use %run para incluir funções e variáveis de outro notebook no mesmo contexto.

Dica de prova: Retorno e timeout: dbutils.notebook.run + dbutils.notebook.exit; inclusão de código: %run.

Referência: Orquestrar notebooks com dbutils.notebook.run

Questão 11 de 12 · Preparar e processar dados

Um hospital quer replicar para o Unity Catalog, de forma incremental e com baixa latência, 60 tabelas de um SQL Server on-premises que o workspace alcança pela rede privada. A equipe decidiu usar o Lakeflow Connect. O que é necessário para a captura incremental das alterações?

Resposta: A) Habilitar change tracking ou CDC no SQL Server e configurar o gateway e o pipeline

Por quê: O conector de SQL Server exige change tracking ou CDC habilitado na origem. Na arquitetura com gateway, há dois pipelines (gateway de ingestão contínuo e pipeline de ingestão); há também a opção de CDC integrado, com um pipeline único que usa uma conexão do Unity Catalog.

Dica de prova: Lakeflow Connect para SQL Server: change tracking ou CDC na origem + gateway e pipeline de ingestão.

Referência: Conector de ingestão do SQL Server

Questão 12 de 12 · Proteger e governar objetos do Unity Catalog

A Construtora Pilar guarda a senha do banco de origem no Azure Key Vault kv-pilar-prd, como o segredo senha-erp. Os notebooks não podem ter a senha em texto nem copiá-la para outro cofre, e a rotação continua sendo feita no Key Vault pela equipe de segurança. O que você deve fazer?

Resposta: D) Criar um escopo de segredo apoiado no Azure Key Vault e ler a senha no notebook com dbutils.secrets.get(scope, key)

Por quê: Escopos de segredo apoiados no Azure Key Vault são uma referência somente leitura ao cofre: os segredos são criados e girados no Azure, e o Azure Databricks os lê em tempo de execução com dbutils.secrets.get, redigindo o valor na saída.

Dica de prova: Segredo que já vive no Key Vault: escopo apoiado no Key Vault + dbutils.secrets.get.

Referência: Gerenciamento de segredos
